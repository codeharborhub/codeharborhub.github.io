Imagine someone hands you a page of numbers with no labels: 28, 31, 30, 29. What are they? Temperatures? Ages? Scores? The numbers mean nothing until you know what they describe. In a table, **headings give every cell its meaning.**

Sighted readers glance up at the top row, or left at the first column, and understand a cell at once. A screen reader user cannot glance. They depend on your HTML to say which heading belongs to which cell. That is the job of the `<th>` element and its `scope` attribute. In this lesson, you will learn to use them correctly, a skill that makes the biggest single difference in table accessibility.

## What Is a `<th>`?

`<th>` stands for **table header cell**. It sits in a row just like a `<td>`, but it carries a different meaning: "this cell is a label for other cells."

| | `<td>` | `<th>` |
| :-- | :-- | :-- |
| Meaning | Data | A label for data |
| Default look | Normal text, left-aligned | **Bold**, centered |
| Screen readers | Read as a value | Announced as the heading for related cells |
| Can have `scope` | No | **Yes** |

```html title="index.html"

    <th>City</th>
    <th>Temperature (°C)</th>
  </tr>
  <tr>
    <td>Mumbai</td>
    <td>31</td>
  </tr>
  <tr>
    <td>Cairo</td>
    <td>28</td>
  </tr>
</table>
```

When a screen reader lands on the cell "31," it can say: **"Temperature in degrees Celsius, 31."** That sentence exists only because you used `<th>`.

## Why Not Just Make a `<td>` Bold?

It looks the same, but it means nothing.

<Tabs>
<TabItem value="bad" label="Looks like a heading" default>

```html
<tr>
  <td><strong>City</strong></td>
  <td><strong>Temperature (°C)</strong></td>
</tr>
```

</TabItem>
<TabItem value="good" label="Is a heading">

```html
<tr>
  <th>City</th>
  <th>Temperature (°C)</th>
</tr>
```

</TabItem>
</Tabs>

With bold `<td>` cells, the browser has no idea these are labels. A screen reader would read "City, Temperature" as two ordinary values, and then "Mumbai, 31" without ever connecting them to their labels. Search engines and other tools also lose the structure.

:::info The rule of thumb
**Style is CSS's job. Meaning is HTML's job.** If a cell *labels* other cells, it is a `<th>`, whatever it looks like.
:::

## Column Headers and Row Headers

Headings can label a **column** (reading down) or a **row** (reading across).

### Column Headers

These sit at the top of a column and describe every cell below.

```text
┌─────────┬────────────┐
│  City   │ Temperature│   ← column headers (th)
├─────────┼────────────┤
│ Mumbai  │    31      │
│ Cairo   │    28      │
└─────────┴────────────┘
```

### Row Headers

These sit at the start of a row and describe every cell to the right. In a table of people, for example, each person's name labels that row.

### Both at Once: A Grid Table

In a two-way table, such as a weekly timetable, you have both. The top row labels the days, and the left column labels the times.

<Tabs>
<TabItem value="code" label="HTML Code" default>

```html title="index.html"
<table>
  <tr>
    <td></td>
    <th scope="col">Monday</th>
    <th scope="col">Tuesday</th>
  </tr>
  <tr>
    <th scope="row">09:00</th>
    <td>HTML</td>
    <td>CSS</td>
  </tr>
  <tr>
    <th scope="row">11:00</th>
    <td>Practice</td>
    <td>Project</td>
  </tr>
</table>
```

</TabItem>

## The `scope` Attribute

`scope` tells the browser (and assistive technology) **which cells a `<th>` labels**.

| Value | Meaning | Use for |
| :-- | :-- | :-- |
| `col` | Labels the cells **below** it in its column | Column headers |
| `row` | Labels the cells **to the right** of it in its row | Row headers |
| `colgroup` | Labels a whole group of columns | Headers over a `<colgroup>` (advanced) |
| `rowgroup` | Labels a whole group of rows | Headers over a `<tbody>` (advanced) |

```html
<th scope="col">Price</th>      <!-- labels everything below -->
<th scope="row">Notebook</th>   <!-- labels everything to the right -->
```

### Do I Always Need `scope`?

Modern browsers can often guess: a `<th>` in the first row is probably a column header, and a `<th>` at the start of a row is probably a row header. But **guessing is not guaranteed**, and assistive tools differ. Adding `scope` removes the doubt, so it is a good habit for every `<th>`.

:::tip Simple rule
Add `scope="col"` to column headers and `scope="row"` to row headers. Leave `colgroup` and `rowgroup` for complex tables.
:::

## The Empty Corner Cell

In a two-way table, the top-left cell has no heading to describe, since it sits above the row headers and beside the column headers. You have three options:

| Option | Code | When to use |
| :-- | :-- | :-- |
| Leave it empty | `<td></td>` | The simplest, usually fine |
| Label it | `<th scope="col">Time</th>` | When the row headers need a name |
| Hide a label from sight | `<td><span class="sr-only">Time</span></td>` | Visually empty, but still named for screen readers |

A label such as "Time" in the corner helps everyone, because it names what the row headers are. Choose it when the meaning is not obvious.

```html
<tr>
  <th scope="col">Time</th>
  <th scope="col">Monday</th>
  <th scope="col">Tuesday</th>
</tr>
```

## Long Headings: The `abbr` Attribute

A screen reader repeats a heading for every cell it reads in that column. A long heading, such as "Average monthly rainfall in millimeters," becomes tiring. The `abbr` attribute gives assistive technology a shorter version.

```html
<th scope="col" abbr="Rainfall">Average monthly rainfall (mm)</th>
```

Sighted users see the full heading. Some screen readers may announce the short "Rainfall" for each cell. Support varies, so also try to keep headings reasonably short in the first place.

## Styling Headings

Because `<th>` is a real element, you can style it directly with CSS.

```css title="style.css"
th {
  background: #e2e8f0;
  text-align: left;
}

thead th {
  background: #0f172a;
  color: #ffffff;
}

th[scope="row"] {
  font-weight: 600;
  background: #f8fafc;
}
```

| Goal | CSS |
| :-- | :-- |
| Left-align headings (instead of centered) | `th { text-align: left; }` |
| Right-align a numeric column's heading | `th.num { text-align: right; }` |
| Different style for row headers | `th[scope="row"] { ... }` |
| Different style for column headers | `th[scope="col"] { ... }` |
| Keep headings visible while scrolling | `thead th { position: sticky; top: 0; }` |

Notice how the `scope` attribute doubles as a **styling hook**, a nice bonus of using it.

## Headings in Different Layouts

### 1. Headings Across the Top (Most Common)

```html
<tr>
  <th scope="col">Name</th>
  <th scope="col">Role</th>
</tr>
```

### 2. Headings Down the Side

For data where each row is a "thing" with properties, the first cell of each row can be a row header.

```html
<tr>
  <th scope="row">Name</th>
  <td>Aisha Khan</td>
</tr>
<tr>
  <th scope="row">Role</th>
  <td>Developer</td>
</tr>
```

### 3. Headings on Both Sides

The grid table you built above: `scope="col"` along the top, and `scope="row"` down the left.

### 4. Headings That Span Columns

When a heading covers several columns (for example "Q1" over "Jan, Feb, Mar"), you merge cells with `colspan`. You will learn that in [Colspan and Rowspan](./colspan-rowspan), and the accessible way to label such tables in [Table Accessibility](./table-accessibility).

## Global Audience Notes

- **Write headings in the language of the page,** and keep them short and plain. Translation tools handle short labels best.
- **Put units in the heading,** such as "Temperature (°C)" or "Price (USD)," instead of repeating them in every cell.
- **Be specific.** "Date of birth" is clearer than "Date," and "Amount (EUR)" is clearer than "Amount."
- **In right-to-left languages,** the column order flips when `dir="rtl"` is set, and headings should follow.

## Common Mistakes to Avoid

1. **Bold `<td>` cells instead of `<th>`.** Looks right, means nothing.
2. **Using `<th>` just to make text bold or centered** in cells that are not labels. Use CSS.
3. **Leaving out `scope`.** It is easy to add and removes guesswork.
4. **Wrong `scope` value,** such as `scope="row"` on a top-row heading.
5. **Empty `<th>` cells.** An empty header has no name. Use `<td>` for an empty corner, or a label.
6. **Vague headings** like "Value" or "Info."
7. **Very long headings,** repeated for every cell. Shorten them, or use `abbr`.
8. **No heading row at all.** Every data table needs labels.
9. **Putting units in every cell** instead of the heading.
10. **Relying on color alone** to tell headings from data. The element itself carries the meaning.

5. Style `th[scope="row"]` differently from `th[scope="col"]`.

## Key Takeaways

- `<th>` marks a cell as a **label**. `<td>` marks it as **data**. Meaning belongs in the HTML, and looks belong in the CSS.
- Use `scope="col"` for column headers and `scope="row"` for row headers.
- Headings travel with every cell, so a screen reader user always knows what a value means.
- Keep headings short, specific, and unit-aware, and never leave a `<th>` empty.
- Style headings with CSS, using `th[scope]` as a handy hook.
