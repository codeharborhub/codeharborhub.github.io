Packing for a trip, you might write: *passport, charger, umbrella, sunglasses.* It does not matter which one you pack first. They are just **a group of things that belong together**.

In HTML, that kind of group is an **unordered list**. It is the list you will use most often: for features, ingredients, tags, links, requirements, and many other collections. In this lesson, you will learn how it works, what you can put inside it, and how to use it well.

## The Basics: `<ul>` and `<li>`

An unordered list needs two elements:

| Element | Name | Job |
| :-- | :-- | :-- |
| `<ul>` | **U**nordered **L**ist | The container for the whole list |
| `<li>` | **L**ist **I**tem | One item inside the list |

<Tabs>
<TabItem value="code" label="HTML Code" default>

```html title="index.html"
<h3>Pack for the trip</h3>
<ul>
  <li>Passport</li>
  <li>Phone charger</li>
  <li>Umbrella</li>
  <li>Sunglasses</li>
</ul>
```

</TabItem>

Each `<li>` becomes a new line with a **bullet marker**. You do not type the bullets yourself. The browser adds them.

:::info Why "unordered"?
It means the order **does not change the meaning**. Swap "Passport" and "Umbrella," and the list says the same thing. If order does matter, you need an [ordered list](./ordered-lists).
:::

## Default Appearance

Out of the box, browsers style an unordered list like this:

- Each item starts on a **new line**.
- Each item gets a **solid round bullet** (called a *disc*).
- The list is **indented** on the left, usually about 40 pixels, to make room for the bullets.
- The list has some **space above and below** it.

This is only the default. With CSS, you can change the bullets, remove them, or lay the items out in a row. You will learn that in [Styling Lists](./list-styling). For now, here is a quick preview.

<Tabs>
<TabItem value="code" label="HTML Code" default>

```html title="index.html"
<ul style="list-style-type: square;">
  <li>Square markers</li>
  <li>Still the same list</li>
</ul>

<ul style="list-style-type: none;">
  <li>No markers at all</li>
  <li>Still the same list</li>
</ul>
```

</TabItem>

Older HTML used a `type` attribute on `<ul>` to pick bullet shapes. That is now obsolete. Use the CSS property `list-style-type` instead.

### What Can Go Directly Inside `<ul>`?

This is the part beginners often get wrong. The only elements allowed as **direct children** of `<ul>` are `<li>` elements. (Script-supporting elements like `<script>` and `<template>` are also allowed, but you will rarely need them here.)

<Tabs>
<TabItem value="wrong" label="Invalid" default>

```html
<ul>
  <h4>My list</h4>      <!-- heading inside ul -->
  <li>One</li>
  <p>Two</p>            <!-- paragraph inside ul -->
  Three                 <!-- loose text -->
</ul>
```

</TabItem>
<TabItem value="right" label="Valid">

```html
<h4>My list</h4>        <!-- heading goes before the list -->
<ul>
  <li>One</li>
  <li>Two</li>
  <li>Three</li>
</ul>
```

</TabItem>
</Tabs>

Browsers will usually show invalid lists anyway, which is why the mistake goes unnoticed. But screen readers and tools can get confused. Keep the structure clean.

## When to Use an Unordered List

Use `<ul>` when you have a **group of related items where the order does not matter**.

| Good use | Example |
| :-- | :-- |
| Features of a product | Fast, Secure, Free |
| Ingredients | Flour, sugar, eggs |
| Requirements | Laptop, internet, a text editor |
| Tags or categories | HTML, CSS, JavaScript |
| A set of links | Menu items, related articles |
| Pros and cons | Each side as its own list |

### Not a Good Use

- **Steps that must happen in order:** use [`<ol>`](./ordered-lists).
- **Terms with definitions:** use [`<dl>`](./description-lists).
- **A single sentence or idea:** use a paragraph. A list with one item is rarely useful.
- **Layout only:** if you want items side by side and nothing is really a list, use CSS layout on `<div>` elements instead.

## Writing Good List Items

A list is only as useful as its items. These habits make lists easier to scan, and easier to translate.

1. **Keep items short.** Aim for a phrase or one sentence. If an item needs a full paragraph, ask whether a list is the right tool.
2. **Make items parallel.** Start each one the same way. "Install Node," "Create a folder," "Run the server" reads better than a mix of styles.
3. **Be consistent with punctuation.** Use a period after every item if they are full sentences, or none if they are short phrases. Do not mix.
4. **Put the key word first.** People scan the start of each line.
5. **Introduce the list.** A heading or sentence before it ("You will need:") gives context.
6. **Do not nest too deep.** One or two levels is plenty. More makes a list hard to follow.

## The `<menu>` Element: A Close Cousin

You may also meet a `<menu>` element. In modern HTML it is a semantic alternative to `<ul>` for **toolbars and sets of commands** (such as Bold, Italic, Underline buttons). It behaves like `<ul>` and contains `<li>` items.

```html
<menu>
  <li><button type="button">Bold</button></li>
  <li><button type="button">Italic</button></li>
</menu>
```

For ordinary bullet lists and navigation, stick with `<ul>`. It is the choice everyone expects, and the one with the best tool support.

## Accessibility at a Glance

Screen readers announce a real `<ul>` as "list, 4 items," and let users jump between items. This is one more reason to use true lists.

- **Do not fake lists** with `<br />` and dashes. Assistive technology will not announce them as lists.
- **Be careful with `list-style: none`.** In some browsers, removing the bullets can also remove the list semantics from screen readers. If you hide the bullets on a list that is still a list, add `role="list"` to `<ul>`. You will see why in [Accessible Lists](./accessible-lists).

## Common Mistakes to Avoid

1. **Putting text, headings, or `<p>` directly inside `<ul>`.** Only `<li>` is allowed there.
2. **Forgetting to close `<li>` or `<ul>`.** Missing tags can break the layout of everything after the list.
3. **Using `<ul>` for ordered steps.** If someone must follow the sequence, use `<ol>`.
4. **Using a list for a single item.** One bullet is just a sentence.
5. **Faking bullets with characters** like `•`, `-`, or `*` inside paragraphs.
6. **Using `<ul>` only for indentation.** Use CSS margin or padding for spacing.
7. **Using the obsolete `type` attribute.** Choose bullet shapes with CSS `list-style-type`.
8. **Mixed, inconsistent items.** Keep wording and punctuation parallel.

## Practice Time

Open your editor and try these:

1. Write a bullet list of five things you want to learn this year.
2. Add a heading above the list that introduces it.
3. Turn one item into a link, and make another one bold.
4. Make a list of three of your favorite websites as links.
5. Wrap a list of links in `<nav>` to make a simple menu.
6. Write "Pros" and "Cons" lists for a tool you use.
7. Change the bullets to squares, then remove them, using `list-style-type`.
8. Rewrite a messy list so that all items start the same way.
9. Bonus: add a second paragraph inside one `<li>`.

## Key Takeaways

- An unordered list is a `<ul>` with `<li>` items, for groups where order does not matter.
- Only `<li>` elements belong directly inside `<ul>`. An `<li>` itself can hold text, links, images, and more.
- Browsers add bullets and indentation by default. Change them with CSS, not with HTML attributes.
- Menus, link groups, and feature lists are all unordered lists in disguise.
- Write short, parallel items, introduce the list, and always use a real list instead of faking one.
