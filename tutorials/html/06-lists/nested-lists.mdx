Think about a book's table of contents. It lists chapters. Under each chapter, it lists sections. Under some sections, it lists subsections. The information has a **tree shape**: big groups hold smaller groups, which hold even smaller ones.

A flat list cannot show that. For a tree, HTML lets you put **a list inside a list**. This is called a **nested list**, and it is how outlines, sub-menus, folder structures, and multi-level instructions are built. The idea is simple, but there is one rule that beginners get wrong again and again. This lesson makes sure you do not.

## The Golden Rule

> **A nested list goes *inside* an `<li>`, not beside it.**

An inner list is not a separate sibling of the items. It **belongs to** one specific item, the one it describes. So you open an `<li>`, write the item's text, and then place the new list inside the same `<li>` before closing it.

<Tabs>
<TabItem value="code" label="HTML Code" default>

```html title="index.html"
<ul>
  <li>Fruits
    <ul>
      <li>Apple</li>
      <li>Mango</li>
    </ul>
  </li>
  <li>Vegetables
    <ul>
      <li>Carrot</li>
      <li>Spinach</li>
    </ul>
  </li>
</ul>
```

Read the structure like a family tree:

- The outer `<ul>` has **two** items: "Fruits" and "Vegetables."
- Each of those items **owns** an inner `<ul>`.
- The inner list is a **child of its `<li>`**, so it shows indented under its parent.

### The Mistake to Avoid

Putting the inner list directly inside the outer `<ul>`, as a neighbor of the `<li>` items, is invalid.

<Tabs>
<TabItem value="wrong" label="Invalid" default>

```html
<ul>
  <li>Fruits</li>
  <ul>               <!-- ❌ a ul directly inside a ul -->
    <li>Apple</li>
    <li>Mango</li>
  </ul>
  <li>Vegetables</li>
</ul>
```

</TabItem>
<TabItem value="right" label="Valid">

```html
<ul>
  <li>Fruits
    <ul>             <!-- ✅ the ul sits inside the li -->
      <li>Apple</li>
      <li>Mango</li>
    </ul>
  </li>
  <li>Vegetables</li>
</ul>
```

</TabItem>
</Tabs>

:::warning Why it matters even though it "works"
Browsers usually still indent the invalid version, so it looks right. But the structure is wrong: the sub-list does not belong to any item. Screen readers may announce the levels incorrectly, CSS rules that target `li > ul` will not match, and validators will flag it. Fix the structure, not just the look.
:::

## Where Exactly Does the Inner List Go?

The inner list can appear after the item's text, inside the same `<li>`. If you want to style or link the text, wrap it so the inner list stays separate:

```html
<li>
  <a href="/html">HTML</a>   <!-- the item's own content -->
  <ul>                       <!-- its sub-list -->
    <li><a href="/html/lists">Lists</a></li>
  </ul>
</li>
```

Always write the item's own text **before** the nested list. The text names the group, and the list holds its members.

## Mixing List Types

You can combine list types freely. The rule stays the same: the inner list goes inside an `<li>`.

| Outer | Inner | Good for |
| :-- | :-- | :-- |
| `<ol>` | `<ul>` | Steps that each have unordered notes or options |
| `<ul>` | `<ol>` | Groups where one group has a sequence |
| `<ul>` | `<dl>` | Categories that hold term-and-meaning pairs |
| Any | Any | Whatever the content needs |

<Tabs>
<TabItem value="code" label="HTML Code" default>

<ol>
  <li>Create a folder named <code>my-site</code>.</li>

    <ul>
      <li><code>index.html</code></li>
      <li><code>style.css</code></li>
      <li><code>script.js</code></li>

  </li>

## How Browsers Change the Markers

For nested **bullet** lists, browsers automatically use a different marker on each level, so you can see the depth.

| Level | Default marker | CSS name |
| :-- | :-- | :-- |
| 1 (top) | Solid circle ● | `disc` |
| 2 | Hollow circle ○ | `circle` |
| 3 and deeper | Solid square ■ | `square` |

### 2. A Navigation Menu with a Sub-Menu

Sub-menus and dropdowns are nested lists. The HTML below is the structure only. CSS (and sometimes JavaScript) turns it into a dropdown.

```html
<nav aria-label="Main">
  <ul>
    <li><a href="/">Home</a></li>
    <li>
      <a href="/courses">Courses</a>
      <ul>
        <li><a href="/courses/html">HTML</a></li>
        <li><a href="/courses/css">CSS</a></li>
        <li><a href="/courses/js">JavaScript</a></li>
      </ul>
    </li>
    <li><a href="/about">About</a></li>
  </ul>
</nav>
```

Even without any CSS, this still works as a clear, accessible outline of the site. That is the benefit of building structure first.

## Numbering Levels as 1, 1.1, 1.2

Legal documents and technical specs often number sub-items as **1.1**, **1.2**, and **2.1**. HTML does not do this on its own, but a small CSS trick called **counters** does.

```css title="style.css"
ol.outline {
  counter-reset: item;
  list-style: none;
  padding-left: 0;
}

ol.outline li {
  counter-increment: item;
}

ol.outline li::before {
  content: counters(item, ".") " ";
  font-weight: 700;
}

ol.outline ol {
  counter-reset: item;
  list-style: none;
  padding-left: 1.5rem;
}
```

```html title="index.html"
<ol class="outline">
  <li>Introduction
    <ol>
      <li>Purpose</li>
      <li>Scope</li>
    </ol>
  </li>
  <li>Method</li>
</ol>
```

The result reads: **1** Introduction, **1.1** Purpose, **1.2** Scope, **2** Method. The `counters()` function joins the number of every level with a dot. You will learn more about counters in [Styling Lists](./list-styling).

## How Deep Should You Go?

You can nest as deeply as you like, but you should not.

- **Two levels** is comfortable for almost everyone.
- **Three levels** is the practical limit for most pages.
- **Four or more** is a sign to rethink: break the content into separate sections with headings, or into several pages.

Deep nesting is hard to read on a small phone screen, because each level pushes the text further to the right. It is also tiring for screen reader users, who hear every level announced.

:::tip A simple test
If you need to scroll sideways, or squint to see which list an item belongs to, the nesting is too deep. Flatten it with headings.
:::

## Accessibility at a Glance

- Screen readers announce nesting, such as "list, 3 items, nested level 2," so people know where they are in the tree. **This only works when your structure is correct.** The inner list must be inside an `<li>`.
- Keep the level count low. Every level is more to listen to.
- Make each parent item a **clear label** for its children. "Fruits" works. "Other" does not.
- Do not use nested lists just for indentation. Use CSS for spacing.
- In navigation, a `<nav>` with a clear `aria-label` plus nested lists gives screen reader users a quick map of your site.

## Common Mistakes to Avoid

1. **Placing the inner list beside the `<li>`**, directly inside `<ul>` or `<ol>`. It belongs inside the `<li>`.
2. **Closing the `<li>` before the inner list.** Put the nested list **before** the closing `</li>`.
3. **Mismatched or missing closing tags.** Deep trees make this easy. Indent your code consistently so each pair lines up.
4. **Nesting too deep.** More than three levels is hard to read.
5. **Using nesting for indentation only.** If it is not a real hierarchy, do not nest.
6. **Typing manual numbers like "1.1" in the text.** Use counters, so numbers update by themselves.
7. **Vague parent labels** such as "More" or "Other."
8. **Forgetting that numbered levels look the same** unless you set `type` or CSS.

## Key Takeaways

- A nested list is a list inside an `<li>`. That is the golden rule.
- You can nest `<ul>`, `<ol>`, and `<dl>` in any combination.
- Browsers change bullet markers by level. Numbered levels need `type` or CSS to look different.
- Outlines, sub-menus, file trees, and comment threads are all nested lists.
- Keep nesting shallow, label parents clearly, and let CSS handle indentation and multi-level numbers.
