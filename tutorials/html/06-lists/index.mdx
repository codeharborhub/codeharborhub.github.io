Think about the last time you went shopping, followed a recipe, or checked a to-do list. You did not read a long paragraph. You read **short lines, one after another**. Lists are one of the oldest and most natural ways humans organize information, and the web is full of them.

Even where you do not notice them, lists are working. A navigation menu is a list of links. A table of contents is a list of sections. A set of product features, a series of steps, a glossary of terms: all lists. In this section, you will learn how HTML marks them up, so that your content is easy to scan for people and easy to understand for browsers, search engines, and screen readers.

## What You Will Learn

In this section, you will be able to:

- Create **bullet lists** with `<ul>` and `<li>`
- Create **numbered lists** with `<ol>`, and control their start, direction, and numbering style
- Create **term and definition lists** with `<dl>`, `<dt>`, and `<dd>`
- Put lists **inside other lists** the right way
- Change markers, spacing, and layout with **CSS**
- Make lists **accessible** and meaningful for everyone

You should know what an HTML element and an attribute are. If you need a refresher, review [Paragraphs](/tutorials/html/text-content/paragraphs) and [Headings](/tutorials/html/text-content/headings) first.

There are two parts here:

- **`<ul>`** is the **list container**. It says: "a group of related items starts here."
- **`<li>`** is a **list item**. Each one is a single entry in the group.

You will see this "container plus items" pattern in every kind of HTML list.

## The Three Kinds of Lists

HTML gives you three list types. Each answers a different question.

| Type | Elements | Question it answers | Example |
| :-- | :-- | :-- | :-- |
| **Unordered list** | `<ul>` and `<li>` | "What are the items?" (order does not matter) | Ingredients, features, tags |
| **Ordered list** | `<ol>` and `<li>` | "What are the items **in sequence**?" (order matters) | Steps, rankings, instructions |
| **Description list** | `<dl>`, `<dt>`, and `<dd>` | "What is this term, and what does it mean?" | Glossaries, FAQs, metadata |

Let's see all three side by side.

<TabItem value="code" label="HTML Code" default>

```html title="index.html"
<!-- 1. Unordered: order does not matter -->
<ul>
  <li>Flour</li>
  <li>Eggs</li>
  <li>Milk</li>
</ul>

<!-- 2. Ordered: order matters -->
<ol>
  <li>Mix the dry ingredients.</li>
  <li>Add the eggs and milk.</li>

</ol>

<dl>
```

## Which List Should I Use?

The most common beginner question is "ul or ol?" Use this quick test.

> **If you shuffled the items, would the meaning change?**

- **No:** use `<ul>`. A shopping list works in any order.
- **Yes:** use `<ol>`. Recipe steps in the wrong order ruin the dish.
- **Is each entry a name paired with a description?** Use `<dl>`.

| Content | Best list | Why |
| :-- | :-- | :-- |
| Items to pack for a trip | `<ul>` | Any order is fine |
| Steps to install a tool | `<ol>` | You must follow the sequence |
| Top 5 programming languages | `<ol>` | The ranking is the point |
| Features of a product | `<ul>` | They are equal in importance |
| Glossary of tech words | `<dl>` | Each term has a definition |
| A website's main menu | `<ul>` | A group of related links |
| Author, date, and category of an article | `<dl>` | Names paired with values |

:::tip Do not choose by looks
Beginners sometimes pick `<ol>` because they like numbers, or `<ul>` because they like bullets. Pick by **meaning**. You can change how a list looks with CSS later, but you cannot fix meaning with CSS.
:::

## Why Not Just Use Paragraphs or `<br />`?

You *could* type items on separate lines with `<br />`, or start each line with a dash. It would look like a list. But it would not **be** a list.

<Tabs>
<TabItem value="fake" label="Fake list" default>

```html
<p>
  - HTML<br />
  - CSS<br />
  - JavaScript
</p>
```

</TabItem>
<TabItem value="real" label="Real list">

```html
<ul>
  <li>HTML</li>
  <li>CSS</li>
  <li>JavaScript</li>
</ul>
```

</TabItem>
</Tabs>

A real list gives you things a fake one cannot:

- **Screen readers announce it.** Users hear "list, 3 items," and can jump from item to item.
- **Browsers and search engines understand it.** They know these lines belong together.
- **CSS can style it.** Spacing, markers, and layout are easy to control.
- **It is easy to maintain.** Adding, moving, or removing an item is simple and safe.

## Rules That Apply to Every List

A few rules hold for all three list types. Learn them once and you will avoid most mistakes.

1. **Only `<li>` goes directly inside `<ul>` and `<ol>`.** Text, headings, or paragraphs placed straight inside them are invalid.
2. **Only `<dt>` and `<dd>` go inside `<dl>`.** You can also group each pair in a `<div>`.
3. **Anything can go inside an `<li>`:** text, links, images, even other lists.
4. **Do not skip levels or mix up the containers.** A nested list belongs *inside* an `<li>`, not beside it.
5. **Do not use lists only for indentation.** Lists carry meaning. If the content is not a list, do not mark it as one.

<TabItem value="wrong" label="Invalid" default>

```html
<ul>
  <p>HTML</p>
  <li>CSS</li>
  Some loose text
</ul>
```

</TabItem>
<TabItem value="right" label="Valid">

```html
<ul>
  <li>HTML</li>
  <li>CSS</li>
  <li>Some text, now inside an item</li>
</ul>
```

## Common Beginner Mistakes

Here are a few traps worth knowing about before you start. Each one has a lesson later.

| Mistake | What goes wrong | Where you will fix it |
| :-- | :-- | :-- |
| Using `<br />` and dashes to fake a list | Screen readers and search engines do not see a list | This page |
| Choosing `<ol>` or `<ul>` by looks | Wrong meaning, wrong announcements | [Unordered Lists](./lists/unordered-lists), [Ordered Lists](./lists/ordered-lists) |
| Putting text or `<p>` directly inside `<ul>` | Invalid HTML | [Unordered Lists](./lists/unordered-lists) |
| Placing a nested list outside an `<li>` | Broken structure | [Nested Lists](./lists/nested-lists) |
| Using `<dl>` for ordinary bullet items | Terms and definitions that do not exist | [Description Lists](./lists/description-lists) |
| Removing bullets with CSS and losing the list meaning | Some screen readers stop announcing the list | [Accessible Lists](./lists/accessible-lists) |

## Lists for a Global Audience

Lists travel across languages and cultures well, but a few habits help.

- **Keep items short and parallel.** Start each item the same way ("Install...", "Create...", "Run..."). Translation tools handle short, regular lines best.
- **Remember that numbering styles differ.** Some languages use their own numerals, and right-to-left languages place markers on the right. CSS can handle both.
- **Do not rely on the visual marker alone.** In an ordered list, the meaning of "step 3" should be clear from the content too.
- **Set the `lang` attribute** on your page so assistive tools read the list in the right language.

## Key Takeaways

- HTML has three list types: `<ul>` for unordered items, `<ol>` for ordered items, and `<dl>` for terms and descriptions.
- Choose by meaning. If shuffling the items would change the sense, use `<ol>`.
- Only `<li>` belongs directly inside `<ul>` and `<ol>`, and only `<dt>` and `<dd>` inside `<dl>`.
- Lists are everywhere: menus, steps, glossaries, and features. Real lists help screen readers, search engines, and you.
- Keep items short and parallel, so your content works well across languages.
