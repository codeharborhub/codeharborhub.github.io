A page with only text is like a book with no pictures. It can be great, but a photo of a harbor at sunrise, a chart that shows a trend, or a diagram that explains a machine can say in one second what takes a paragraph to describe.

Images are also where web pages most often go wrong. They can make a page slow, break on small screens, shut out people who cannot see them, and cost visitors real money on mobile data. The good news is that every one of those problems has a simple, well-known solution in HTML. In this section, you will learn how to add images that look sharp, load fast, and work for everyone.

## What You Will Learn

In this section, you will be able to:

- Add an image to a page with the **`<img>` element**
- Write a correct **`src`** and a meaningful **`alt`** text
- Set **`width` and `height`** so your page does not jump around while loading
- Pick the right **image format** for photos, graphics, and icons
- Serve the right size to every screen with **responsive images**, `srcset`, and `sizes`
- Choose formats and crops with the **`<picture>` element**
- Speed up your pages with **lazy loading**
- Add captions with **`<figure>` and `<figcaption>`**
- Make images **accessible** to people who cannot see them

:::info Prerequisites
You should know how to write basic HTML elements and how file paths work. If you need a refresher, read [Relative URLs](/tutorials/html/links-and-navigation/relative-urls) first.
:::

## The Anatomy of an Image

An `<img>` is a **void element**: it has no content and no closing tag, like `<br />` and `<hr />`. All the information lives in its attributes.

```html
<img src="images/harbor.jpg" alt="Fishing boats at sunrise" width="300" height="160" />
```

| Attribute | What it does | Required? |
| :-- | :-- | :-- |
| `src` | The **address** of the image file | Yes |
| `alt` | A **text alternative** for people and tools that cannot see the image | Yes, always |
| `width` and `height` | The image's **size in pixels**, so the browser can reserve space | Strongly recommended |
| `loading` | Whether to load the image right away or later (`lazy`) | Optional |
| `srcset` and `sizes` | Several versions of the image for different screens | Optional |

## Three Questions to Ask About Every Image

Before you add an image, ask yourself these three questions. They guide almost every decision in this section.

| Question | Why it matters | Where you will learn it |
| :-- | :-- | :-- |
| **Does the image mean something?** | Meaningful images need helpful `alt` text. Decorative ones need an empty `alt` | [Src and Alt](./images/src-and-alt), [Accessible Images](./images/accessible-images) |
| **How big will it be on screen?** | A huge file on a small phone wastes data and time | [Responsive Images](./images/responsive-images), [Srcset and Sizes](./images/srcset-and-sizes) |
| **What is the best file type?** | A photo, a logo, and a chart each have a best format | [Image Formats](./images/image-formats) |

## Choosing a Format at a Glance

You will study formats in depth later. This quick map gets you started.

| Your image is... | Good choice | Why |
| :-- | :-- | :-- |
| A photograph | JPEG, WebP, or AVIF | Small files for rich colors |
| A logo, icon, or simple illustration | SVG | Sharp at any size, and tiny |
| A screenshot or image with sharp text | PNG or WebP | Keeps edges crisp |
| A short animation | Animated WebP or video | Much smaller than a GIF |

## Images and Page Speed

Images are usually the **heaviest** part of a web page. On many sites, they make up more than half of everything a visitor has to download. A few habits make a big difference.

1. **Resize before you upload.** Do not publish a 6000-pixel photo to show it at 600 pixels.
2. **Use modern formats** like WebP and AVIF when they fit.
3. **Give the browser sizes** with `width` and `height`, so the page does not jump.
4. **Offer several versions** with `srcset`, so phones download smaller files.
5. **Load later what is not visible yet** with `loading="lazy"`.

Visitors around the world use slow connections and pay for each megabyte. Efficient images are not just a technical nicety. They make your page usable and affordable for everyone.

## Images and Accessibility

Some visitors cannot see your images. They may use a screen reader, have a very slow connection where images have not loaded, or use a text-only browser. The `alt` attribute is how your page speaks to them.

<Tabs>
<TabItem value="bad" label="Not helpful" default>

```html
<img src="chart.png" alt="chart" />
<img src="photo1.jpg" alt="IMG_20261003_0457.jpg" />
<img src="team.jpg" />
```

</TabItem>
<TabItem value="good" label="Helpful">

```html
<img src="chart.png" alt="Bar chart: course sign-ups doubled between March and June" />
<img src="photo1.jpg" alt="Students building a website together in a classroom" />
<img src="divider.svg" alt="" />
```

The last image is purely decorative, so its `alt` is intentionally empty.

</TabItem>
</Tabs>

:::tip The one-sentence test
Imagine reading the page aloud to a friend over the phone. What would you say in place of the picture? That sentence is your `alt` text.
:::

## Common Beginner Mistakes

Here are a few traps worth knowing about before you start. Each one has its own lesson later.

| Mistake | What goes wrong | Where you will fix it |
| :-- | :-- | :-- |
| Leaving out `alt`, or writing "image" | Screen reader users get nothing, or noise | [Src and Alt](./images/src-and-alt) |
| A wrong file path | The image shows as a broken icon | [Src and Alt](./images/src-and-alt) |
| No `width` and `height` | The text jumps down when the image finally loads | [Width and Height](./images/width-and-height) |
| Using a huge photo for a small space | Slow pages and wasted data | [Responsive Images](./images/responsive-images) |
| Using PNG for every photo | Files several times bigger than needed | [Image Formats](./images/image-formats) |
| Loading every image at once | The page feels slow, even for images far below the fold | [Lazy Loading](./images/lazy-loading) |
| Putting important text inside an image | It cannot be searched, translated, or read aloud | [Accessible Images](./images/accessible-images) |
| Using someone else's picture without permission | Copyright trouble | See the tip below |

:::warning Use images you have the right to use
Do not copy pictures from other websites. Use your own photos and drawings, or images with a license that allows reuse, and follow its rules for credit. When in doubt, ask or choose a different picture.
:::

## Images for a Global Audience

Your visitors come from many countries and cultures. A few thoughtful habits help.

- **Write `alt` text in the language of the page,** and set the `lang` attribute.
- **Avoid text inside images.** It cannot be translated by browsers or read aloud. Put the words in HTML instead.
- **Choose pictures that many people can relate to.** Gestures, symbols, and clothing can mean different things in different places.
- **Think about data costs.** Smaller files are kinder to visitors on limited plans.
- **Show diverse people** when your pictures include people.

## Key Takeaways

- Add images with the `<img>` element, which needs `src` and `alt`.
- Write `alt` text that says what the image means. Use `alt=""` for decoration only.
- Set `width` and `height` to keep your layout steady while images load.
- Choose formats, sizes, and loading behavior with page speed and data costs in mind.
- Make every image work for everyone: describe it, caption it when it helps, and keep important text out of pictures.
