export function LinkBuilderDemo() {
  const kinds = {
    email: {label: "Email", sample: "hello@example.com", hint: "An email address"},
    phone: {label: "Phone", sample: "+91 98765 43210", hint: "A phone number with its country code"},
    whatsapp: {label: "Chat app", sample: "+91 98765 43210", hint: "The same number, for a chat link"},
    map: {label: "Map search", sample: "Market Square, Springfield", hint: "A place name or street address"},
  };
  const [kind, setKind] = useState("email");
  const [value, setValue] = useState(kinds.email.sample);
  const [subject, setSubject] = useState("Question about tickets");
  let href = "";
  let warning = "";
  const digits = value.replace(/[^\d+]/g, "");
  if (kind === "email") {
    href = "mailto:" + value.trim() + (subject ? "?subject=" + encodeURIComponent(subject) : "");
    if (!value.includes("@")) warning = "An email address needs an @ sign.";
  } else if (kind === "phone") {
    href = "tel:" + digits;
    if (!digits.startsWith("+")) warning = "Add the country code (for example +91) so the link works from anywhere.";
  } else if (kind === "whatsapp") {
    href = "https://wa.me/" + digits.replace(/\D/g, "");
    if (!digits.startsWith("+")) warning = "Use the full international number, with country code.";
  } else {
    href = "https://www.openstreetmap.org/search?query=" + encodeURIComponent(value.trim());
  }
  const text = kind === "email" ? value.trim() : kind === "map" ? "Find us on the map" : value.trim();
  const code = '<a href="' + href + '">' + text + "</a>";
  return (
    <form onSubmit={(event) => event.preventDefault()}>
      <p style={{margin: "0 0 0.5rem"}}>
        <label htmlFor="lb-kind">Kind of link</label><br />
        <select
          id="lb-kind"
          value={kind}
          onChange={(event) => {
            setKind(event.target.value);
            setValue(kinds[event.target.value].sample);
          }}
        >
          {Object.keys(kinds).map((key) => (<option key={key} value={key}>{kinds[key].label}</option>))}
        </select>
      </p>
      <p style={{margin: "0 0 0.5rem"}}>
        <label htmlFor="lb-value">{kinds[kind].hint}</label><br />
        <input
          type="text"
          id="lb-value"
          value={value}
          onChange={(event) => setValue(event.target.value)}
          style={{width: "100%", maxWidth: "24rem"}}
        />
      </p>
      {kind === "email" ? (
        <p style={{margin: "0 0 0.5rem"}}>
          <label htmlFor="lb-subject">Subject line (optional)</label><br />
          <input
            type="text"
            id="lb-subject"
            value={subject}
            onChange={(event) => setSubject(event.target.value)}
            style={{width: "100%", maxWidth: "24rem"}}
          />
        </p>
      ) : null}
      <pre style={{margin: "0.4rem 0", whiteSpace: "pre-wrap", wordBreak: "break-all"}}><code>{code}</code></pre>
      <p style={{margin: "0 0 0.3rem"}}>
        Try the link:{" "}
        <a href={href} onClick={(event) => event.preventDefault()}>{text}</a>{" "}
        <span style={{fontSize: "0.85em", color: "#64748b"}}>(disabled in this demo)</span>
      </p>
      {warning ? <p role="status" style={{margin: 0, color: "#b45309"}}>{warning}</p> : null}
    </form>
  );
}

When you need to get in touch with someone, you look for a **name, an email, a phone number**, or maybe a place to visit. The **`<address>`** element tells browsers and assistive tools that a piece of content is exactly that: **contact information**.

The name is a trap. `<address>` is **not** for any postal address you happen to mention. It has a narrow, specific meaning. This lesson explains what it is for, what it is not for, how to build useful contact links, and how to handle privacy and international formats.

A few details worth noticing:

- The **`<br />`** line breaks are a **correct** use of `<br>`: in a postal address, the line break is part of the content, not just spacing.

## What `<address>` Is For

The specification gives it one precise job:

> The `<address>` element represents the **contact information** for its **nearest `<article>` ancestor**, or, if there is none, for the **page** (the `<body>`).

So it answers one of two questions:

| Where it sits | It means | Example |
| :-- | :-- | :-- |
| Inside an `<article>` | **How to reach the author or owner of that article** | "Written by Ada. Write to ada@example.com" |
| Anywhere else on the page | **How to reach the owner of the whole page or site** | The company's contact details in the footer |

## What `<address>` Is **Not** For

Because of its name, people use `<address>` for **every** address. That is wrong, and the specification is clear about it.

| Situation | Use `<address>`? | What to use instead |
| :-- | :-- | :-- |
| Your company's contact details in the footer | **Yes** | |
| The author's contact details in an article | **Yes** | |
| A **delivery address** the visitor types in a form | **No** | Form fields. See [Autocomplete](/tutorials/html/forms/autocomplete) |
| An address **mentioned in the text** ("The festival is held at 12 Market Square.") | **No** | Plain text in a paragraph |
| A **list of other businesses'** addresses (a directory) | **No** | A list, a table, or a description list |
| A **publication date**, "last updated", or opening hours | **No** | `<time>`, or a paragraph |
| A **postal address as a sample** in a tutorial | **No** | A code block or a paragraph |
| An **email address** in a sentence ("Email us at ...") | Not needed | A link in the paragraph |

Also, the **content** of `<address>` should be **only contact information**. The specification says not to put other things in it, such as a publication date or a long biography. And `<address>` **cannot contain** headings, sectioning elements (`<article>`, `<section>`, `<nav>`, `<aside>`), a `<header>`, a `<footer>`, or another `<address>`.

:::note What about a list of branches?
A "Our offices" page with ten branch addresses is not the contact information for the page's owner in the narrow sense, though many sites mark them up with `<address>` anyway. The safe approach: use `<address>` for the **primary** contact details, and use a list with a `<h3>` for each branch (plus clear text), or an `<address>` inside each branch's own `<article>`, if each branch has its own page.
:::

## Building Contact Links

Contact details are most useful as **links** that do something. Here is the toolbox. Try the builder, and watch the `href` change.

<Tabs>
<TabItem value="code" label="HTML Code" default>

```html title="index.html"
<!-- Email, with an optional subject -->
<a href="mailto:hello@example.com?subject=Question%20about%20tickets">hello@example.com</a>

<!-- Phone: the href has no spaces, and has the country code -->
<a href="tel:+919876543210">+91 98765 43210</a>

<!-- Chat link -->
<a href="https://wa.me/919876543210">Message us</a>

<!-- Map search (a place name, URL-encoded) -->
<a href="https://www.openstreetmap.org/search?query=Market%20Square%2C%20Springfield">Find us on the map</a>
```

```js title="script.js"
// Build safe links from values in code, never by gluing raw text together
const subject = "Question about tickets & prices";
const href = "mailto:hello@example.com?subject=" + encodeURIComponent(subject);

console.log(href);
// mailto:hello@example.com?subject=Question%20about%20tickets%20%26%20prices
```

### Rules for each link type

| Link | Rules |
| :-- | :-- |
| `mailto:` | Optional `?subject=` and `&body=`, **URL-encoded** with `encodeURIComponent`. Opens the visitor's email app, so also offer a contact form for people without one |
| `tel:` | Use the **international format** with `+` and the country code, with **no spaces or punctuation** in the `href` (`tel:+919876543210`). The visible text can be formatted for people |
| Chat links | Follow the service's own link format, and offer another way to reach you |
| Map links | Link to a map for a place, and **also write the address as text**, because a map is not enough for everyone |

:::tip Write the visible text as clearly as the link
A screen reader reads the visible text: "hello at example dot com". For phone numbers, spaces help it read the digits in groups. A link such as "Call us on +91 98765 43210" is clearer than "Click here".
:::

## Where to Put It

| Place | Use |
| :-- | :-- |
| In the **page footer** | The site or company contact details (the most common use) |
| In an **article's footer or header** | How to reach the author |
| On a **contact page**, in `<main>` | The main way to reach the organisation. Combine with a contact form |
| In a **"Contact us" section** of a landing page | Inside a `<section>` with a heading |

An `<address>` has no heading of its own. If it needs one ("Contact us"), put the heading **outside** it, in the surrounding `<section>`.

## Styling

```css title="style.css"
address {
  font-style: normal;          /* remove the default italics */
  line-height: 1.6;
}

address a {
  display: inline-block;       /* easier to tap on phones */
  padding-block: 0.25rem;
}
```

Keep contact links **large enough to tap** (at least 24 by 24 CSS pixels, ideally 44).

## Accessibility at a Glance

- **Use real links** (`mailto:` and `tel:`), with clear visible text.
- **Do not put contact information only in an image** (a picture of a phone number cannot be read, copied, or tapped).
- **Offer more than one way to get in touch:** email, phone, a form, and a postal address. Some visitors cannot use the phone, or cannot use a form.
- **Write the address as text,** not only as a map link or an embedded map.
- **Say when you answer:** "Mon to Fri, 9:00 to 17:00 (UTC+05:30)", in a nearby paragraph.
- **Do not rely on icons** (an envelope or a phone) without text.
- **Keep the font style readable:** if you keep the default italics, make sure the text is still easy to read.
- **Give a contact form real labels,** and clear error messages. See [Accessible Forms](/tutorials/html/forms/accessible-forms).

## Security and Privacy Notes

- **Spam bots harvest email addresses** from pages. Publishing one invites spam. Options: use a contact form, use a role address (such as `hello@`) that you can filter, or accept the risk knowingly. Hiding the address with JavaScript tricks stops simple bots only, and also breaks the page for some real visitors.
- **Never publish a private person's contact details** (home address, personal phone) without their clear permission. This can expose people to harassment. Business contact details are different, but still need consent from the people named.
- **Data protection laws** (such as the GDPR in Europe, and similar laws elsewhere) treat names, emails, and phone numbers as personal data. Publish only what you need, and be ready to remove it on request.
- **Build `mailto:` and `tel:` links safely.** If a value comes from user input, **encode** it, and do not allow line breaks or extra parameters to be injected into the link.
- **Beware of phishing:** a link that shows one address and goes to another is deceptive. Keep the visible text and the real target in agreement.
- **Third-party maps and chat widgets** may track your visitors. Load them only with consent, and give the address as plain text as well.
- **Open outside links safely:** `rel="noopener"` for map and chat links in a new tab.

## Global Audience Notes

- **Use the international phone format** (`+`, country code, then the number) in both the `href` and the visible text, so the number works from any country.
- **Address formats differ** a lot: the order of lines, whether there is a postal code, whether there are states or districts, and which script is used. Write addresses in the way **that country's post** expects, and include the **country**.
- **Provide the local-language version** of an address (and a Latin-letter version, if your visitors may need it), so couriers and taxi drivers can read it.
- **Where street addresses are informal,** add landmarks, a map link, or a location code such as a Plus Code.
- **Right-to-left pages:** phone numbers and email addresses are left-to-right text. Wrap them in `<bdi>` or set `dir="ltr"` so punctuation such as the `+` does not jump to the wrong side:

```html
<p dir="rtl">اتصل بنا: <bdi><a href="tel:+971501234567">+971 50 123 4567</a></bdi></p>
```

- **Show hours with a time zone,** and mention languages your support speaks.
- **Do not assume every visitor has a phone, or an email app.** Offer a form or chat as well.
- **Currency and regional contact numbers:** list a local number for each region you serve, if you can.

## Common Mistakes to Avoid

1. **Using `<address>` for every postal address,** including addresses in the story text.
2. **Using it for a form's delivery address.**
3. **Putting a publication date, opening hours, or a biography inside it.**
4. **Putting a heading or a `<footer>` inside it.**
5. **Leaving the default italics on** without meaning to.
6. **Plain-text email and phone numbers** that are not links.
7. **A `tel:` link with spaces or no country code.**
8. **Putting contact details only in an image.**
9. **Publishing a private person's home address or phone.**
10. **Building `mailto:` links from unencoded user input.**
11. **Only a map link and no written address.**
12. **Using `<br>` for spacing everywhere,** instead of only for real line breaks in addresses.

## Key Takeaways

- `<address>` holds **contact information** for the nearest article's author or owner, or else for the whole page.
- It is **not** for arbitrary postal addresses, form delivery addresses, or other people's addresses.
- Put only contact details in it. It cannot contain headings, sectioning elements, a header, a footer, or another address.
- Make contact details **real links**: `mailto:` (with encoded subject) and `tel:` (international format, no spaces).
- Reset the default italics with `font-style: normal`, and use `<br>` only for true line breaks.
- Write the address as text as well as a map link, and offer more than one way to get in touch.
- Protect privacy: beware of spam harvesting, publish only what people agreed to, and encode link values.
- For international audiences, use `+` country codes, local address formats, and `<bdi>` for numbers on right-to-left pages.
