import {useState, useRef} from 'react';

export function StandAloneDemo() {
  const items = [
    {label: "A blog post", answer: "article", why: "It can be published, shared, and read on its own."},
    {label: "A news story", answer: "article", why: "A complete piece that could appear in a feed or on another site."},
    {label: "A reader's comment", answer: "article", why: "A self-contained contribution, even though it sits inside a bigger page."},
    {label: "A product card in a shop list", answer: "article", why: "Each card is a complete, independent item that could be listed elsewhere."},
    {label: "The 'Pricing' part of a landing page", answer: "section", why: "It is a themed part of a bigger page, and means little on its own."},
    {label: "Chapter 3 of a long guide", answer: "section", why: "A chapter belongs to the whole guide."},
    {label: "A list of related links beside a story", answer: "aside", why: "Related but separate from the main point."},
    {label: "A wrapper that lays cards out in a grid", answer: "div", why: "It has no meaning of its own, only layout."},
  ];
  const [index, setIndex] = useState(0);
  const [guess, setGuess] = useState(null);
  const item = items[index];
  const options = ["article", "section", "aside", "div"];
  return (
    <div>
      <p style={{margin: "0 0 0.5rem"}}>
        <label htmlFor="sa-pick">Choose a piece of content</label><br />
        <select
          id="sa-pick"
          value={index}
          onChange={(event) => {
            setIndex(Number(event.target.value));
            setGuess(null);
          }}
        >
          {items.map((entry, i) => (<option key={entry.label} value={i}>{entry.label}</option>))}
        </select>
      </p>
      <p style={{margin: "0 0 0.4rem"}}>Which element fits best?</p>
      <p style={{margin: "0 0 0.5rem"}}>
        {options.map((option) => (
          <button
            type="button"
            key={option}
            onClick={() => setGuess(option)}
            style={{marginRight: "0.4rem", fontFamily: "monospace"}}
          >
            {option}
          </button>
        ))}
      </p>
      {guess ? (
        <p role="status" style={{margin: 0, color: guess === item.answer ? "#15803d" : "#b91c1c"}}>
          {guess === item.answer ? "Correct. " : "Not quite: the best fit is " + item.answer + ". "}
          {item.why}
        </p>
      ) : null}
    </div>
  );
}

export function TreeDemo() {
  const rootRef = useRef(null);
  const [lines, setLines] = useState(null);
  const watched = ["ARTICLE", "SECTION", "HEADER", "FOOTER", "ASIDE", "MAIN"];
  const walk = (node, depth, out) => {
    Array.from(node.children).forEach((child) => {
      if (watched.includes(child.tagName)) {
        out.push({depth, tag: child.tagName.toLowerCase(), label: child.getAttribute("data-label") || ""});
        walk(child, depth + 1, out);
      } else {
        walk(child, depth, out);
      }
    });
    return out;
  };
  const box = {border: "1px dashed #94a3b8", borderRadius: "6px", padding: "0.4rem 0.6rem", marginTop: "0.3rem"};
  return (
    <div>
      <div ref={rootRef}>
        <main data-label="the page's content">
          <article data-label="the blog post" style={box}>
            <header data-label="title and author" style={box}>
              <strong>How to shape a loaf</strong> · By Ada · <time dateTime="2026-04-12">12 April 2026</time>
            </header>
            <section data-label="the body" style={box}>
              <p style={{margin: 0}}>Start with a round of dough…</p>
            </section>
            <section data-label="the comments" style={box}>
              <strong>2 comments</strong>
              <article data-label="comment 1" style={box}>
                <p style={{margin: 0}}>Great tips! – Sam</p>
              </article>
              <article data-label="comment 2" style={box}>
                <p style={{margin: 0}}>Mine came out flat. – Priya</p>
              </article>
            </section>
            <footer data-label="post footer" style={box}>Filed under: Bread</footer>
          </article>
        </main>
      </div>
      <p style={{margin: "0.6rem 0"}}>
        <button type="button" onClick={() => setLines(walk(rootRef.current, 0, []))}>
          Show the structure
        </button>
      </p>
      {lines ? (

Imagine cutting a single story out of a newspaper. It has its own headline, its own author, and it makes complete sense even if you pin it on a wall by itself. Now imagine cutting out a random paragraph from the middle of page 7. It would not make much sense alone.

That difference is exactly what the **`<article>`** element is about: a **self-contained piece of content** that stands on its own. It is one of the most useful elements for content-heavy sites, and its meaning is clearer than you might expect once you know the one test to apply.

Like the other structural elements, `<article>` has **no default style**, so the border and width above come from CSS. What it adds is **meaning**: screen readers announce an "article", some offer a shortcut to move between articles, and reader modes and feed tools use it to find the content worth keeping.

## The Stand-Alone Test

To decide whether something is an article, ask:

> **Could this be lifted out of the page and still make complete sense? Would it work in an RSS feed, in an email, or on another website?**

If yes, it is an `<article>`. The specification describes it as a "self-contained composition that is, in principle, independently distributable or reusable."

## What Counts as an Article

| Content | Why it is an article |
| :-- | :-- |
| A blog post or magazine article | The classic case |
| A news story | A complete report |
| A forum post | A contribution that stands by itself |
| A reader's **comment** | Self-contained, even inside a bigger page |
| A **product card** in a list | A complete, independent item |
| A social media post or tweet | Independently shareable |
| A widget or gadget that is a complete unit | For example, an interactive weather card |
| A review | A complete opinion piece |

The word "article" is a little misleading. It is **not only for newspaper-style writing**. Anything self-contained, small or large, qualifies.

## Articles and Sections: Nesting Both Ways

Articles and sections often contain each other:

- A **blog article** contains several **sections** (introduction, steps, conclusion).
- A **"Latest posts" section** contains several **articles** (one for each post).
- A post's **comments section** contains **articles** (one for each comment).

Notice that the comments are **articles inside an article**. The specification says that when articles are nested, the inner ones are **related to** the outer one. That is exactly right for comments on a post.

## Headings Inside Articles

Every article should have a **heading** that names it. Where it goes depends on the page:

| Page | Article heading |
| :-- | :-- |
| A page about **one** article (a blog post page) | `<h1>` is the usual choice, because the article **is** the page |
| A **list** of articles (a blog index) | The page has an `<h1>` ("Blog"), and each article has an `<h2>` |
| Comments inside an article | One level lower than the article's own sections |

Always keep levels in order without skipping, and choose levels for **structure**, not size. See [Section](./section) for why.

## Dates and Authors

### The `<time>` element

`<time>` gives a machine-readable version of a date or time, even if the visible text is written in a friendly way:

```html
<time datetime="2026-04-12">12 April 2026</time>
<time datetime="2026-04-12T09:30:00+05:30">Saturday morning</time>
<time datetime="PT5M">5 min read</time>
```

| `datetime` format | Meaning | Example |
| :-- | :-- | :-- |
| `yyyy-mm-dd` | A date | `2026-04-12` |
| `yyyy-mm-ddThh:mm` plus an offset | A date and time with a time zone | `2026-04-12T09:30:00+05:30` |
| `yyyy-mm` | A month | `2026-04` |
| `PT5M` | A duration (5 minutes) | `PT5M` |

The visible text can be in **any language and style**. The `datetime` value is what machines read, so search engines, calendars, and translation tools can understand it.

### The author

Link the author to a page about them, and use `rel="author"` when that is who wrote the article:

```html
<p>By <a href="/authors/ada" rel="author">Ada Lovelace</a></p>
```

For contact details of the article's author, you can use the `<address>` element. See [Address](./address).

## A Clickable Card, Done Well

Product and blog **cards** are typically articles, and designers want the whole card to be clickable. The common mistake is to wrap the entire card in one big `<a>`, which makes a screen reader read **everything** as one long link name. A better pattern: one real link on the **heading**, stretched across the card with CSS.

```html
<article class="card">
  <img src="/img/sourdough.jpg" alt="" width="320" height="200" />
  <h3><a href="/posts/sourdough">A simple sourdough loaf</a></h3>
  <p>Four ingredients, one patient weekend.</p>
</article>
```

```css title="style.css"
.card {
  position: relative;          /* the anchor point for the stretched link */
}

.card a::after {
  content: "";
  position: absolute;
  inset: 0;                    /* the invisible link now covers the whole card */
}

.card a:focus-visible::after {
  outline: 3px solid #1d4ed8;  /* keep a visible focus ring around the card */
}
```

The link text is short and clear ("A simple sourdough loaf"), screen reader users hear one link per card, and mouse users can click anywhere on it. The picture uses `alt=""` because it only decorates the link next to it.

## User-Generated Content: Handle With Care

Comments, reviews, and forum posts are articles written by **strangers**. Treat them as untrusted:

- **Escape everything.** Show comment text as plain text (`textContent`), or sanitise any HTML you allow with a trusted library.
- **Mark user links** with `rel="ugc nofollow noopener"`, so search engines do not treat them as endorsements, and the new page cannot control yours.
- **Limit length and rate,** and moderate or filter abuse.
- **Never trust the author name, date, or ids** in a submitted comment. Set them on the server.
- **Protect personal data.** Show only the name and details the person agreed to show.

```html
<article>
  <h3>Sam</h3>
  <p>Great tips! See <a href="https://example.com" rel="ugc nofollow noopener">my blog</a>.</p>
</article>
```

See [Secure Form Design](/tutorials/html/forms/secure-form-design).

## Accessibility at a Glance

- **Give every article a heading,** at the right level.
- **Use real `<time>`, headings, lists, and links** inside, not styled `<div>`s.
- **Name important articles** with `aria-labelledby` pointing at their heading, if they appear in a list that users move between.
- **Do not wrap a whole card in one big link.** Link the heading, and stretch it with CSS.
- **Keep reading order logical:** header, content, then footer, in the HTML itself.
- **Give images useful `alt` text** (or `alt=""` when decorative).
- **Write short, descriptive link text** such as "Read more about sourdough", and not just "Read more".
- **Check contrast and focus styles** on cards and links.
- **Keep nested comments readable:** do not indent so deeply that text becomes narrow on small screens.

## Global Audience Notes

- **Set `lang`** on `<html>`, and on an `<article>` that is in another language: `<article lang="hi">`.
- **Use `<time datetime>`** so dates stay machine-readable, whatever language or format you show. Format the visible text for the visitor's locale (for example with `Intl.DateTimeFormat`).
- **Right-to-left articles:** use `dir="rtl"` on an article written in Arabic or Hebrew, even on a left-to-right page.
- **Reading time** ("5 min read") is a rough guide. Languages differ in reading speed, so label it as an estimate.
- **Translated copies** of an article should link to each other with `hreflang`, so visitors and search engines find the right version.
- **Keep headlines plain and short,** so they translate and fit small screens.
- **Test with long names and long words,** which are common in some languages, and allow them to wrap.

## Common Mistakes to Avoid

1. **Using `<article>` for any chunk of content.** It must stand on its own.
2. **Using `<section>` for a blog post or comment.** Those are articles.
3. **An article with no heading.**
4. **Wrapping a whole card in one giant link,** so its name is a paragraph long.
5. **Using `<div>` for items** that clearly are articles.
6. **Writing dates only as text,** with no `<time datetime>`.
7. **Showing user comments unescaped.**
8. **Leaving `rel="ugc nofollow"` off links in comments.**
9. **Putting `<main>` inside an `<article>`.**
10. **Using `<article>` only to style something.**
11. **Skipping heading levels** inside nested articles.
12. **Treating an article's footer as the page footer.** It belongs to the article.

## Key Takeaways

- `<article>` marks **self-contained** content that makes sense on its own and could be reused elsewhere.
- Blog posts, news stories, comments, reviews, and product cards are all articles.
- The test: would it work in a feed, an email, or another site? If it is only a themed part of a bigger whole, use `<section>`.
- Articles can have a `<header>` and `<footer>`, can contain sections, and can nest (comments inside a post).
- Every article needs a **heading**, at the right level.
- Use `<time datetime>` for dates, and `rel="author"` for the writer.
- Make cards clickable with **one link on the heading** stretched by CSS, not a giant link around everything.
- Treat comments and other user content as untrusted: escape, sanitise, and mark links with `rel="ugc nofollow noopener"`.
