import {useState, useRef} from 'react';

export function BuilderDemo() {
  const parts = [
    {key: "copyright", label: "Copyright line", always: true},
    {key: "legal", label: "Privacy, terms, and cookie settings links"},
    {key: "a11y", label: "Accessibility statement link"},
    {key: "contact", label: "Contact details"},
    {key: "sitemap", label: "Site links"},
    {key: "social", label: "Social media links"},
    {key: "language", label: "Language links"},
  ];
  const [on, setOn] = useState({copyright: true, legal: true, a11y: true, contact: false, sitemap: false, social: false, language: false});
  const toggle = (key) => setOn({...on, [key]: !on[key]});
  const lines = ["<footer>"];
  if (on.sitemap) {
    lines.push('  <nav aria-label="Footer">', "    <ul>", '      <li><a href="/programme">Programme</a></li>', '      <li><a href="/tickets">Tickets</a></li>', "    </ul>", "  </nav>");
  }
  if (on.contact) {
    lines.push("  <address>", '    <a href="mailto:hello@example.com">hello@example.com</a>', "  </address>");
  }
  if (on.social) {
    lines.push('  <ul aria-label="Social media">', '    <li><a href="https://example.com/festival" rel="noopener">Festival on Example</a></li>', "  </ul>");
  }
  if (on.language) {
    lines.push('  <ul aria-label="Language">', '    <li><a href="/en/" hreflang="en" lang="en">English</a></li>', '    <li><a href="/hi/" hreflang="hi" lang="hi">हिन्दी</a></li>', "  </ul>");
  }
  const legal = [];
  if (on.legal) {
    legal.push('<a href="/privacy">Privacy</a>', '<a href="/terms">Terms</a>', '<button type="button" id="cookie-settings">Cookie settings</button>');
  }
  if (on.a11y) {
    legal.push('<a href="/accessibility">Accessibility statement</a>');
  }
  if (legal.length > 0) {
    lines.push('  <ul aria-label="Legal">');
    legal.forEach((item) => lines.push("    <li>" + item + "</li>"));
    lines.push("  </ul>");
  }
  lines.push("  <p><small>&copy; 2026 Spring Bread Festival. All rights reserved.</small></p>", "</footer>");
  const code = lines.join("\n");
  return (
    <div>
      <fieldset style={{margin: "0 0 0.6rem"}}>
        <legend>What does your footer need?</legend>
        {parts.map((part) => (
          <label key={part.key} style={{display: "block"}}>
            <input type="checkbox" checked={on[part.key]} disabled={part.always} onChange={() => toggle(part.key)} /> {part.label}
          </label>
        ))}
      </fieldset>
      <pre style={{margin: 0, whiteSpace: "pre-wrap", fontSize: "0.85em"}}><code>{code}</code></pre>
    </div>
  );
}

At the end of a letter, you sign off. At the end of a book, you find the publisher, the year, and the notes. At the end of a web page, you expect to find **who made it, how to reach them, and the small print**. The **`<footer>`** element marks that closing content.

It looks almost identical to `<header>`, and follows the same idea: it can be used for the whole page **or** for one article or section, and its meaning depends on where you put it. This lesson shows what belongs inside, what visitors expect to find there, and how to build one that works for everyone.

As with `<header>`, a `<footer>` has **no default look**. It is a plain block, and the line and spacing above are CSS. Its job is meaning.

## Two Kinds of Footer

The same element means different things, depending on **where it sits**:

| Where it sits | What it is | Announced as |
| :-- | :-- | :-- |
| **Directly in `<body>`** (not inside another sectioning element) | The footer for the **whole page** | **contentinfo** landmark |
| Inside `<article>` | The footer for **that article**: tags, author note, share links | Nothing special |
| Inside `<section>` | The footer for **that section**: "See all" link, notes | Nothing special |
| Inside `<main>`, `<aside>`, or `<nav>` | The footer for that region | Nothing special |

A page can have **many** footers, but only the page-level one is the `contentinfo` landmark. A page should have **one**.

```html
<body>
  <main>
    <article>
      <h1>How to shape a loaf</h1>
      <p>…</p>

      <footer>                        <!-- the article's footer: no landmark -->
        <p>Filed under: <a href="/topics/bread">Bread</a></p>
      </footer>
    </article>
  </main>

  <footer>                            <!-- the page footer: contentinfo landmark -->
    <p><small>&copy; 2026 My Site</small></p>
  </footer>
</body>
```

A footer does **not** have to be at the very bottom of the screen. It is about meaning: **closing information** for its parent. And, like `<header>`, it cannot contain another `<header>` or `<footer>`.

## What Belongs in a Page Footer

Visitors have learned where to look for certain things. Putting them in a footer is a convention worth following.

| Typical content | Notes |
| :-- | :-- |
| **Copyright** line | Use `<small>`, and a `&copy;` symbol |
| **Legal links** | Privacy policy, terms, cookie settings |
| **Accessibility statement** | Required or expected in many places |
| **Contact information** | An email, phone number, or address, with `<address>` |
| **Site links** | A secondary menu or sitemap, in a `<nav aria-label="Footer">` |
| **Social media links** | With text names, not only icons |
| **Language or region selector** | Links with `lang` and `hreflang` |
| **"Back to top"** link | Helpful on long pages |
| **Newsletter sign-up** | With a proper label (see [Accessible Forms](/tutorials/html/forms/accessible-forms)) |
| **Credits and licences** | Photo credits, a content licence |

What does **not** belong:

- The **main page content** (that is `<main>`).
- The **primary navigation** (that is the header's `<nav>`).
- **Related content** or ads (that is `<aside>`).
- **Essential instructions** that visitors must read before they can use the page.

## The `<small>` Element

`<small>` marks **side comments and fine print**: copyright, legal notices, and licensing. It is **not** a way to make text tiny.

```html
<p><small>&copy; 2026 Spring Bread Festival. All rights reserved.</small></p>
<p><small>Photos by Ada, licensed under CC BY 4.0.</small></p>
```

Browsers show it in a slightly smaller size by default, but its **meaning** is "fine print." Do not use it for long paragraphs of important text, because tiny text is hard to read.

### A Year That Stays Correct

A hard-coded "2026" goes out of date. Options:

- **Static site or build step:** put the year in your template, and rebuild each year.
- **In the browser:** a small script, with the year written in HTML as a fallback:

```html
<p><small>&copy; <span id="year">2026</span> Spring Bread Festival</small></p>
```

```js title="script.js"
document.getElementById("year").textContent = new Date().getFullYear();
```

The copyright notice only needs the year of first publication (and, if you like, a range such as 2024 to 2026). It is not legal advice, so check what applies to you.

## Legal and Privacy Links Visitors Expect

Footers are where people look for the "boring but important" links. Depending on your site and your visitors' countries, you may need or want:

| Link | Why |
| :-- | :-- |
| **Privacy policy** | Explains what data you collect and why. Required in many places when you collect personal data |
| **Terms of use** | The rules for using your site or service |
| **Cookie settings** ("Manage cookies") | Lets visitors change their consent at any time. Use a real `<button>`, since it triggers an action rather than navigating |
| **Accessibility statement** | Tells visitors how accessible the site is and how to report problems |
| **Imprint** (for example, "Impressum") | Legally required in some countries to identify the site's operator |
| **Contact and complaints** | A real way to reach a person |
| **Refund and shipping policies** | For shops |

## Keeping the Footer at the Bottom

On a page with little content, the footer can float up under the text and leave an empty gap. The fix is a small CSS grid on `<body>`. Tick the box to see it at work.

```html title="index.html"
  <header>Header</header>
  <main>A very short page. Not much content here.</main>
  <footer>Footer</footer>
</body>
```

```css title="style.css"
body {
  min-height: 100vh;
  margin: 0;
  display: grid;
  grid-template-rows: auto 1fr auto;   /* header, main (stretches), footer */
}
```

## A Footer Inside an Article or Section

An article's footer holds details **about that article**:

```html
<article>
  <h2>How to shape a loaf</h2>
  <p>Start with a round of dough…</p>

  <footer>
    <p>Filed under: <a href="/topics/bread">Bread</a>, <a href="/topics/beginners">Beginners</a></p>
    <p>Share: <a href="/share/email">Email</a> · <a href="/share/copy">Copy link</a></p>
  </footer>
</article>
```

It is a good home for tags, categories, author notes, licence details, and "next" and "previous" links belonging to that item. A section can do the same, with something like a "See all news" link. These footers are **not** landmarks.

## Accessibility at a Glance

- **Use one page-level `<footer>`,** so there is a single `contentinfo` landmark.
- **Name footer navigation** with `aria-label="Footer"` when the page has other `<nav>` regions.
- **Use lists** for groups of links, so the number of links is announced, and label them if there are several.
- **Give social icons text names:** `aria-label="Festival on Example"`, or visible text. An icon alone is not enough.
- **Use a `<button>` for actions** such as "Cookie settings", and a link for navigation.
- **Keep text readable:** `<small>` must not be tiny. Aim for at least 14 to 16 px with good contrast (4.5 to 1 or better).
- **Make touch targets big enough** (at least 24 by 24 CSS pixels, ideally 44), with space between links.
- **Do not use a footer as the only place** for something visitors urgently need.
- **Add a "Back to top" link** on long pages, and make sure it moves focus.

## Security and Privacy Notes

- **Do not put sensitive information in the footer,** such as internal email addresses, staff phone numbers, server details, or version numbers that help attackers.
- **Public email addresses attract spam.** Use a contact form, or accept the risk knowingly.
- **Open outside links safely:** `rel="noopener"` (and `rel="noreferrer"` if you do not want to share the page address) for social and partner links.
- **Third-party badges and widgets** in footers (payment logos, review widgets, chat, analytics) can load tracking scripts. Load only trusted ones, and respect the visitor's cookie consent.
- **Link to your real privacy policy,** and make sure it matches what the site does.
- **Escape anything dynamic,** such as a visitor's name or a country shown in the footer.
- **Do not show admin or login links** that expose how your system is built. Hiding a link protects nothing, so always enforce access on the server.

## Global Audience Notes

- **Laws differ by country.** Cookie consent, privacy rights, imprint, tax details, and accessibility statements are required in different places. Check the rules for the countries your visitors live in.
- **Provide a language and region selector** where you serve several. Write each language name in its own language, and mark it with `lang`.
- **Use `<address>` and time-zone-aware contact details:** say "Mon to Fri, 9:00 to 17:00 (UTC+05:30)" for support hours.
- **Show currency and units clearly** if your footer lists prices or shipping.
- **Right-to-left pages:** flex rows reverse by themselves with `dir="rtl"`. Use logical properties such as `margin-inline-end`.
- **Footers get long in translation,** since legal words are lengthy. Let links wrap onto several lines.
- **Do not depend on icons that mean different things in different cultures.** Add text.
- **Keep the footer light.** Large logo walls and widgets slow every page, a real cost on low-bandwidth connections.

## Common Mistakes to Avoid

1. **Using `<footer>` for the main content,** just because it is at the bottom.
2. **Nesting a `<footer>` or `<header>` inside a footer.**
3. **Several page-level footers,** or `role="contentinfo"` on more than one.
4. **Using `<footer>` for side content** that belongs in an `<aside>`.
5. **Social icons with no accessible name.**
6. **Tiny, pale `<small>` text** that is hard to read.
7. **A "Cookie settings" link that does nothing** or is a `<div>` instead of a `<button>`.
8. **A copyright year that is years out of date.**
9. **Unlabelled footer menus,** when the page has other `<nav>` regions.
10. **A footer floating mid-screen** on short pages.
11. **Putting essential information only in the footer.**
12. **Loading trackers in the footer** without consent.

<summary>1. What is the `<footer>` element for?</summary>

It holds closing information for its parent: for a page, things like copyright, legal links, contact details, and site links. For an article or section, it holds details about that item, such as tags or related links.

<details>
<summary>2. When is a footer the `contentinfo` landmark?</summary>

When it is the page-level footer, directly in `<body>` and not inside `<article>`, `<aside>`, `<main>`, `<nav>`, or `<section>`. Footers inside those elements are just footers for that part.

</details>

<details>
<summary>3. Does a footer have to be at the bottom of the screen?</summary>

No. The element is about meaning, not position. It is usually at the bottom, but CSS decides where it is displayed.

</details>

<details>
<summary>4. What is `<small>` for?</summary>

Side comments and fine print, such as copyright and legal notices. It is not a way to make text tiny, and it should stay readable.

</details>

<details>
<summary>5. How do you keep a footer at the bottom of a short page?</summary>

Give `<body>` a minimum height of the viewport and a grid with rows `auto 1fr auto`, so the main area stretches and pushes the footer down.

</details>

<details>
<summary>6. Why should a "Cookie settings" control be a `<button>`?</summary>

It performs an action (opening a dialog) rather than navigating to another page, so a real button gives correct keyboard behaviour and meaning.

</details>

## Key Takeaways

- `<footer>` holds **closing information** for a page, article, or section.
- Only the **page-level** footer is the `contentinfo` landmark. Use one per page.
- Typical contents: copyright in `<small>`, legal and privacy links, an accessibility statement, contact details, site links, and social links with text names.
- A footer cannot contain another `<header>` or `<footer>`, and is not for main content, primary navigation, or sidebars.
- Label footer navigation, use lists for link groups, and use buttons for actions such as cookie settings.
- Keep it at the bottom of short pages with CSS grid, and keep text readable and targets large.
- Check legal requirements for the countries you serve, and load third-party footer widgets only with consent.
- Do not hide anything essential, or anything sensitive, in a footer.
