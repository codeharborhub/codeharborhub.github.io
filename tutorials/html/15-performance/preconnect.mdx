export function pickOrigins(text, siteOrigin) {
  const map = {};
  const origins = [];
  const bad = [];
  text.split("\n").forEach(function (line) {
    const s = line.trim();
    if (s === "") return;
    let u;
    try {
      u = new URL(s);
    } catch (e) {
      bad.push(s);
      return;
    }
    if (u.protocol !== "https:" && u.protocol !== "http:") {
      bad.push(s);
      return;
    }
    if (siteOrigin && u.origin === siteOrigin) return;
    const isFont = /\.(woff2?|ttf|otf)(\?|$)/i.test(u.pathname) || /fonts|gstatic/i.test(u.hostname);
    if (!map[u.origin]) {
      map[u.origin] = {origin: u.origin, count: 0, cors: false};
      origins.push(map[u.origin]);
    }
    map[u.origin].count += 1;
    if (isFont) map[u.origin].cors = true;
  });
  origins.sort(function (a, b) { return b.count - a.count; });
  return {origins: origins, bad: bad};
}

export function buildOriginHints(origins, choices) {
  const lines = [];
  origins.forEach(function (o) {
    const choice = choices[o.origin] || (o.count >= 2 ? "preconnect" : "dns-prefetch");
    if (choice === "preconnect") {
      lines.push('<link rel="preconnect" href="' + o.origin + '"' + (o.cors ? " crossorigin" : "") + ">");
      lines.push('<link rel="dns-prefetch" href="' + o.origin + '">');
    } else if (choice === "dns-prefetch") {
      lines.push('<link rel="dns-prefetch" href="' + o.origin + '">');
    }
  });
  return lines.join("\n");
}

# Preconnect in HTML

When your page needs a file from a new server, the browser has to do three things before the first byte of that file can arrive: look up the server's address, open a connection, and agree on encryption. On a slow or distant network, that setup alone can take a noticeable fraction of a second.

`<link rel="preconnect">` tells the browser to do all of that setup early, while it is busy with other work. When the page finally asks for a file from that server, the line is already open. It is one of the best hints for a page that depends on a few outside servers, and it is the one most often overused.

## What Preconnect Does

For a new `https` host, preconnect does all of the setup steps that come before a request:

1. **DNS lookup**: find the server's address.
2. **Connect**: open a line to the server.
3. **Secure handshake**: agree on encryption.

It sends **no request** for any file. The browser simply keeps the connection ready for when the page needs it. Compared with `dns-prefetch`, which only does step 1, preconnect can save much more, and costs a little more too.

:::warning
An idle connection does not stay open forever. Browsers close unused connections after a short time, so a preconnect for something the page uses much later may be wasted. The exact time varies by browser.
:::

## The `crossorigin` Question

Here is the part that surprises people. Browsers keep **two separate sets** of connections to the same host: one for requests made with credentials (such as cookies) and one for requests made without. They cannot share a connection.

- A plain `preconnect` (no `crossorigin`) prepares the **credentialed** connection. Images, stylesheets, and classic scripts use it.
- A `preconnect` with `crossorigin` prepares the **anonymous** connection. Fonts, `fetch()` calls, and anything with a `crossorigin` attribute use it.

If you hint the wrong one, the real request cannot use it, and the browser opens a new connection anyway. You paid for a connection nobody used.

| The page later loads | Hint it needs |
| :-- | :-- |
| An image, stylesheet, or classic script from the host | `preconnect` (no `crossorigin`) |
| A font, or data with `fetch()` | `preconnect` with `crossorigin` |
| A mix of both | Both hints, one with and one without |

Go back to the Connection Lab and try each combination. If a host serves both kinds, you may need both hints, but remember that each one is a connection you are paying for. Browsers differ in small details, so check in DevTools which connections are really used.

## How Many Is Too Many?

Each preconnect uses time, memory, and a connection on the visitor's device and on the server. Browsers may also limit how many early connections they will open. A sensible rule of thumb is to keep preconnect for **two to four** origins that the page needs in its first seconds, and use `dns-prefetch` for the rest. Lighthouse has an audit that suggests which origins are worth preconnecting and warns about having too many, but treat that as advice and test.

Good candidates are:

- The host that serves your **first-screen images** (a CDN, for example)
- The host that serves your **fonts**
- A host your **main script** calls straight away

Poor candidates are anything used late, anything that needs consent first, and anything you only link to.

## Preconnect vs DNS Prefetch

| | `dns-prefetch` | `preconnect` |
| :-- | :-- | :-- |
| Does the DNS lookup | Yes | Yes |
| Opens the connection and handshake | No | Yes |
| Cost | Tiny | Small, but a connection stays open |
| Needs `crossorigin` | No | Sometimes |
| Best for | Hosts you may need later | Hosts you need very soon |

Use them together for important hosts: `preconnect` does the work, and `dns-prefetch` is a fallback for browsers that do not support it. See the [DNS Prefetch lesson](./dns-prefetch) for the reasoning.

## Preconnect from a Header or a Script

Like other hints, preconnect can be sent from the server as a header:

```http
Link: <https://cdn.example.com>; rel=preconnect
Link: <https://fonts.gstatic.com>; rel=preconnect; crossorigin
```

You can also add it with JavaScript when the visitor shows interest, for example on hover over a button that will load a third-party widget. That keeps the cost for people who do not need it close to zero:

```js
const btn = document.querySelector("#open-chat");
btn.addEventListener("mouseenter", function () {
  const link = document.createElement("link");
  link.rel = "preconnect";
  link.href = "https://chat.example.com";
  document.head.appendChild(link);
}, { once: true });
```

## Checking That It Worked

1. Open DevTools, then **Network**, and reload.
2. Click a request to the hinted host and open its **Timing** tab. The **Initial connection** and **SSL** parts should be short or missing, because they happened earlier.
3. Look at the **Waterfall** with the connection column shown, if your browser offers it. Fewer new connections means the preconnect was reused.
4. Test on a fresh cache and a slow network, because caching and fast networks can hide the difference.
5. Compare a key number, such as Largest Contentful Paint (LCP), before and after.
6. If the connection is not reused, check `crossorigin` first. It is the most common cause.

## Best Practices

1. **Preconnect only to origins the page needs in its first seconds.**
2. **Keep the list to a few.**
3. **Use `crossorigin` when the files load in CORS mode,** such as fonts.
4. **Hint the credentialed and anonymous connection separately** if the host needs both.
5. **Add `dns-prefetch` as a fallback.**
6. **Use origins only,** with no path.
7. **Add it on interaction** for things that load only when asked.
8. **Remove hints for services you no longer use,** and measure after every change.

## Quick Checklist

- [ ] Each preconnect is for an origin the page uses early
- [ ] Font and `fetch()` hosts have `crossorigin`
- [ ] No more than a few preconnects
- [ ] `dns-prefetch` added as a fallback for the important ones
- [ ] No hint for your own site
- [ ] No hint for hosts that need consent first
- [ ] DevTools shows the connection was reused

## Security and Privacy Notes

- **A preconnect sends no request, but it still reaches out.** The host learns the visitor's network address and some details of the secure handshake, even if the visitor never uses the service. If you need consent before contacting certain services (analytics or advertising, for example), do not hint those hosts until consent is given. This is not legal advice, so check the rules that apply to you.
- **Only preconnect to hosts you trust.** A connection is a relationship. Never build hints from untrusted input, such as user-submitted links.
- **Use https.** Preconnecting to a plain `http` host gives you almost nothing, and sends visitors to an unencrypted service.
- **A broken host costs time.** If a host has a certificate error or never answers, the preconnect wastes effort, and may add warnings to the console. Make sure your page works without it.
- **Idle connections use server resources too,** so a popular page with many preconnects can add load for the service you point at.

## Global Audience Notes

- **Distance makes connections expensive.** A visitor far from the server may wait several round trips for the setup, so preconnect helps most for them. A CDN with servers near visitors reduces the gap.
- **Mobile connections are slower to set up,** and each extra connection costs battery. A short list is kind to them.
- **Some third-party hosts are slow or blocked in some countries.** A preconnect to a host that never answers is wasted time. The page must still work if the host fails.
- **Test from other regions** with a tool such as WebPageTest, and on a modest phone, not only your own fast machine.

## Common Mistakes to Avoid

1. **Forgetting `crossorigin` on font hosts.**
2. **Adding `crossorigin` to image-only hosts,** so the real requests cannot use the connection.
3. **Preconnecting to a dozen hosts.**
4. **Preconnecting to hosts used late,** so the connection closes before it is used.
5. **Preconnecting to your own site.**
6. **Putting a path in the URL.**
7. **Hinting before consent** for services that need it.
8. **Leaving hints for services you removed.**
9. **Using it instead of fixing a late-found file** that `preload` or better HTML would solve.
10. **Never checking** that the connection was reused.

## Key Takeaways

- **Preconnect does the connection setup early:** lookup, connect, and handshake.
- **It names an origin, not a file,** and sends no request.
- **`crossorigin` selects which connection you prepare.** Match it to the later request.
- **Keep the list short:** a few early hosts, with `dns-prefetch` for the rest.
- **Pair it with `dns-prefetch`** as a fallback.
- **Add it on interaction** for things loaded only when asked.
- **Respect privacy:** wait for consent, trust the host, and measure that the connection was reused.
