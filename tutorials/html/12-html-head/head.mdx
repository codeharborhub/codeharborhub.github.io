export function ParserLab() {
  const [source, setSource] = useState(sampleSources.divInHead);
  const doc = new DOMParser().parseFromString(source, "text/html");
  const describe = (element) => {
    const tag = element.tagName.toLowerCase();
    const bits = [];
    ["name", "charset", "rel", "property"].forEach((attr) => {
      if (element.hasAttribute(attr)) bits.push(attr + '="' + element.getAttribute(attr) + '"');
    });
    if (tag === "title") bits.push('"' + element.textContent + '"');
    return "<" + tag + (bits.length ? " " + bits.join(" ") : "") + ">";
  };
  const headItems = Array.from(doc.head.children).map(describe);
  const bodyItems = Array.from(doc.body.children).map(describe);
  const strays = Array.from(doc.body.querySelectorAll("meta, link, title, style, base"));
  const titles = doc.querySelectorAll("title").length;
  const warnings = [];
  if (strays.length > 0) warnings.push(strays.length + " head-type element(s) ended up in the body, so they may not work as intended: " + strays.map(describe).join(", "));
  if (titles > 1) warnings.push("There are " + titles + " title elements. Only the first counts.");
  if (!doc.head.querySelector("meta[charset]")) warnings.push("No meta charset was found in the head.");
  if (!doc.head.querySelector("title") && !doc.querySelector("title")) warnings.push("No title was found.");
  const load = (key) => setSource(sampleSources[key]);
  return (
    <div>
      <p style={{margin: "0 0 0.4rem"}}>
        <button type="button" onClick={() => load("good")}>Good page</button>{" "}
        <button type="button" onClick={() => load("divInHead")}>A div in the head</button>{" "}
        <button type="button" onClick={() => load("noHead")}>No head tag</button>{" "}
        <button type="button" onClick={() => load("twoTitles")}>Two titles</button>
      </p>
      <label htmlFor="parser-source">HTML to parse (edit it freely)</label>
      <textarea id="parser-source" rows={11} value={source} onChange={(event) => setSource(event.target.value)} style={{width: "100%", fontFamily: "monospace", fontSize: "0.85em"}} />
      <div style={{display: "flex", flexWrap: "wrap", gap: "1rem", marginTop: "0.5rem"}}>
        <div style={{flex: "1 1 14rem"}}>
          <strong>Browser put in the head ({headItems.length})</strong>
          <ul style={{margin: "0.3rem 0 0"}}>
            {headItems.length === 0 ? <li>(nothing)</li> : headItems.map((item, index) => (<li key={index}><code>{item}</code></li>))}
          </ul>
        </div>
        <div style={{flex: "1 1 14rem"}}>
          <strong>Browser put in the body ({bodyItems.length})</strong>
          <ul style={{margin: "0.3rem 0 0"}}>
            {bodyItems.length === 0 ? <li>(nothing)</li> : bodyItems.map((item, index) => (<li key={index}><code>{item}</code></li>))}
          </ul>
        </div>
      </div>
      <div role="status" style={{marginTop: "0.5rem"}}>
        {warnings.length === 0 ? (
          <p style={{margin: 0}}>No structure problems found.</p>
        ) : (
          <ul style={{margin: 0}}>
            {warnings.map((warning) => (<li key={warning}>{warning}</li>))}
          </ul>
        )}
      </div>
      <p style={{margin: "0.5rem 0 0", fontSize: "0.9em", color: "#64748b"}}>
        This uses your browser's real HTML parser (<code>DOMParser</code>). Nothing you type is run, and scripts are not executed.
      </p>
    </div>
  );
}

If `<body>` is the stage where your page performs, then **`<head>`** is **backstage**: the crew room, the lighting plan, the script, and the sound check. The audience never sees it, but without it, the show does not start properly.

The `<head>` element is a container for **metadata** and for **links to the files the page needs**. In this lesson you learn what belongs there, what does not, and (importantly) what the browser quietly does when you get it wrong.

## What the Head Is For

The head answers questions the browser asks **before** it shows anything:

| Question | Answered by |
| :-- | :-- |
| How do I read these letters? | `<meta charset>` |
| How wide is the screen? | `<meta name="viewport">` |
| What is this page called? | `<title>` |
| What does this page say about itself? | `<meta name="description">` and others |
| What should it look like? | `<link rel="stylesheet">` and `<style>` |
| What should it do? | `<script>` |
| What picture represents it? | `<link rel="icon">` |
| Where do relative links start? | `<base>` |

## What Is Allowed in the Head

Only these elements may appear directly inside `<head>`:

| Element | Notes |
| :-- | :-- |
| `<title>` | Exactly **one**, required |
| `<meta>` | As many as you need |
| `<link>` | As many as you need |
| `<style>` | CSS inside the page |
| `<script>` | JavaScript or data |
| `<base>` | At most **one** |
| `<noscript>` | Allowed in the head, but it may only contain `<link>`, `<style>`, and `<meta>` there |
| `<template>` | A fragment of markup that script can use later |

Comments are also fine.

### Rules You Should Know

1. **Exactly one `<title>`,** and it must contain only text.
2. **At most one `<base>`,** and it should come before anything that uses a relative address.
3. **`<meta charset>` must be within the first 1024 bytes** of the file.
4. **Do not put visible content in the head.** No `<div>`, `<p>`, `<img>`, or loose text.

## What Happens When You Break the Rules

The HTML parser never gives up. It **repairs** the page. When it meets an element that does not belong in the head, it assumes the head is finished, silently creates the body, and carries on from there.

```html
<head>
  <title>My Page</title>
  <div>Oops</div>                       <!-- the head ends here -->
  <meta name="description" content="…"> <!-- now in the body: ignored by search engines -->
</head>
```

The result is a page that **looks** fine, but where some of your metadata does nothing. These bugs are hard to spot, which is why the Parser Lab above is worth experimenting with.

Common causes:

- A stray `<div>` or text typed in the head
- A **JavaScript snippet** that writes markup into the head
- A third-party snippet that includes a `<noscript><img …></noscript>` in the head (an `<img>` is not allowed there, so it ends the head)
- A missing closing tag, such as an unclosed `<title>`, which swallows the next lines as title text

:::warning An unclosed `<title>` swallows your page
If you forget `</title>`, the browser treats everything that follows as part of the title, until it finds a closing tag. Always check that your tags are closed.
:::

## Do I Need to Write `<head>`?

Technically, the **start and end tags of `<head>` are optional** if the first thing inside is an element. The browser will create the head anyway, as the "No head tag" sample shows.

**But write them anyway.** Explicit tags make the structure obvious to people, avoid edge-case surprises, and match what every tool and tutorial expects.

## A Sensible Order

Order is mostly flexible, but this arrangement avoids problems and helps the page load quickly:

```html
<head>
  <!-- 1. Encoding first, within the first 1024 bytes -->
  <meta charset="utf-8">

  <!-- 2. Viewport and title -->
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Page title | Site name</title>

  <!-- 3. Other metadata -->
  <meta name="description" content="…">
  <link rel="canonical" href="https://example.com/page">
  <link rel="icon" href="/favicon.svg" type="image/svg+xml">

  <!-- 4. Styles, so rendering can start early -->
  <link rel="stylesheet" href="/css/site.css">

  <!-- 5. Scripts last, with defer -->
  <script src="/js/app.js" defer></script>
</head>
```

Why this order?

- The browser must know the **encoding** before it reads text.
- **Styles** should arrive early, so the page appears styled the first time.
- **Plain scripts block the page** while they download and run, so they come late, or use `defer`.

## The Head and Your Docusaurus Site

On this documentation site, you rarely write a `<head>` by hand. Docusaurus builds it for you, and gives you places to add to it:

- **Site-wide:** `docusaurus.config.js` has `headTags`, `stylesheets`, `scripts`, and `favicon`.
- **Per page:** the frontmatter fields `title`, `description`, `keywords`, and `image` become the title and meta tags for that page.
- **Custom tags in a component:** import `Head` from `@docusaurus/Head`, and place `<meta>` or `<link>` inside it.

```jsx
import Head from '@docusaurus/Head';

export default function Example() {
  return (
    <Head>
      <meta name="robots" content="noindex" />
    </Head>
  );
}
```

The tags you write are merged into the page's real `<head>` when the site is built. Understanding what the head is for helps you use those settings well.

## Good Habits

1. **Write `<head>` and `</head>` explicitly.**
2. **Put `charset` first,** then viewport and title.
3. **Give every page its own `<title>` and description.**
4. **Keep the head light:** only what the page truly needs.
5. **Load scripts with `defer`** unless you have a reason not to.
6. **Close every tag,** especially `<title>`.
7. **Check your page** in a validator, and with your browser's developer tools.

## Accessibility Checklist

- [ ] The page has **exactly one** meaningful `<title>`.
- [ ] `lang` is set on `<html>`.
- [ ] The viewport tag **does not** block zooming.
- [ ] Styles that provide focus outlines and contrast load reliably (and are not behind a blocking script).
- [ ] Scripts do not delay the page so much that assistive technology waits for content.
- [ ] If a script sets the title, it **updates it on each page or screen change** in a single-page app.

## Security and Privacy Notes

- **The head is public.** Do not put secrets in comments, meta tags, or inline scripts.
- **Every external `<script>` and `<link rel="stylesheet">` runs with the power of your page.** Use trusted sources, and consider Subresource Integrity with `integrity` and `crossorigin` (see [Third-Party Content Security](/tutorials/html/embedded-content/third-party-content-security)).
- **Inline scripts and styles can be blocked** by a strict Content-Security-Policy. Prefer external files if you use one.
- **Escape anything dynamic.** If a server puts visitor-provided text in the `<title>` or a `<meta>`, encode it, so no one can close the tag and inject their own.
- **Be careful with `<base>`.** An injected base tag can redirect every relative link and form on the page.

## Global Audience Notes

- **Always use `<meta charset="utf-8">`,** and save your file in UTF-8, so every language displays correctly.
- **Write the title and description in the language of the page.**
- **Keep the head small:** visitors on slow or expensive connections feel every extra file.
- **Add `hreflang` links** if the page exists in several languages (see the Link lesson).
- **Avoid scripts that load fonts or tools from servers that are slow or blocked** in some regions, or provide a fallback.

## Common Mistakes to Avoid

1. **A `<div>` or loose text in the head,** which ends it early.
2. **An unclosed `<title>`.**
3. **Two `<title>` elements.**
4. **Two or more `<base>` elements.**
5. **`<meta charset>` too late in the file.**
6. **Plain `<script>` tags in the head,** blocking the page.
7. **Putting `<link>` and `<meta>` tags in the body** by accident.
8. **The same title and description on every page.**
9. **Secrets or private notes in comments.**
10. **Using `async` for scripts that depend on each other.**
11. **A noscript snippet with an image in the head.**
12. **Not checking the result** with the browser's inspector.

## Key Takeaways

- The **head** is the page's backstage: metadata and links to the files it needs.
- Only `title`, `meta`, `link`, `style`, `script`, `base`, `noscript`, and `template` belong there.
- Invalid content **ends the head early,** and later tags land in the body.
- Order: **charset, viewport, title, other metadata, styles, deferred scripts.**
- Use `defer` or `async` so scripts do not block the page.
- The head is public, so keep secrets out, escape dynamic values, and load only trusted files.
- In Docusaurus, use the config, frontmatter, and `@docusaurus/Head` to manage it.
