export function HeadPeek() {
  const [data, setData] = useState(null);
  const short = (text) => {
    const clean = (text || "").replace(/\s+/g, " ").trim();
    return clean.length > 70 ? clean.slice(0, 67) + "…" : clean;
  };
  const read = () => {
    const children = Array.from(document.head.children);
    const rows = children.slice(0, 40).map((element) => {
      const tag = element.tagName.toLowerCase();
      const label = element.getAttribute("name") || element.getAttribute("property") || element.getAttribute("rel") || element.getAttribute("http-equiv") || (element.hasAttribute("charset") ? "charset" : "");
      let detail = "";
      if (tag === "title") detail = element.textContent;
      else if (tag === "style") detail = "(inline CSS)";
      else if (tag === "script") detail = element.getAttribute("src") || "(inline script)";
      else if (tag === "link") detail = element.getAttribute("href");
      else detail = element.getAttribute("content") || element.getAttribute("charset");
      return {tag, label, detail: short(detail)};
    });
    const viewport = document.querySelector('meta[name="viewport"]');
    setData({
      total: children.length,
      shown: rows.length,
      rows,
      facts: [
        ["document.title", document.title],
        ["lang on the html element", document.documentElement.lang || "(not set)"],
        ["Character encoding", document.characterSet],
        ["Rendering mode", document.compatMode === "CSS1Compat" ? "standards mode (good)" : "quirks mode (a problem)"],
        ["Viewport setting", viewport ? viewport.getAttribute("content") : "(none found)"],
      ],
    });
  };
  return (
    <div>
      <p style={{margin: "0 0 0.5rem"}}>
        <button type="button" onClick={read}>Read the head of this page</button>
      </p>
      {data === null ? (
        <p role="status" style={{margin: 0}}>Press the button, and the page will list what is in its own head.</p>
      ) : (
        <div>
          <table>
            <caption>Facts the browser reads from this page</caption>
            <tbody>
              {data.facts.map((fact) => (
                <tr key={fact[0]}><th scope="row" style={{textAlign: "start"}}>{fact[0]}</th><td>{fact[1]}</td></tr>
              ))}
            </tbody>
          </table>
          <p role="status" style={{margin: "0.6rem 0 0.3rem"}}>
            This page's head has <strong>{data.total}</strong> elements{data.total > data.shown ? ", and the first " + data.shown + " are listed" : ""}.
          </p>
          <div style={{maxHeight: "16rem", overflow: "auto", border: "1px solid #cbd5e1", borderRadius: "6px"}}>
            <table style={{margin: 0, width: "100%"}}>
              <thead>
                <tr><th scope="col">Tag</th><th scope="col">Name or rel</th><th scope="col">Value</th></tr>
              </thead>
              <tbody>
                {data.rows.map((row, index) => (
                  <tr key={index}><td><code>{row.tag}</code></td><td>{row.label}</td><td style={{wordBreak: "break-all"}}>{row.detail}</td></tr>
                ))}
              </tbody>
            </table>

      )}

        What you see is whatever this documentation site puts in its head. Tools such as Docusaurus add many tags for you. Your own pages can be much smaller.
      </p>
    </div>

Open any web page, and you see its **body**: the headings, pictures, and links. But every page also has a part you **never see**, called the **head**. It is the page's control room. It holds the title that appears in the browser tab, the instructions that tell the browser which letters to use, which stylesheets to load, and which summary a search engine or a chat app should show when someone shares your page.

The information stored there is called **metadata**: data **about** the page, as opposed to the content **of** the page. A well-made head makes a page load correctly, look right on a phone, rank sensibly in search results, preview nicely when shared, and work for everyone.

## The Smallest Valid Head

Every HTML document needs at least these three things in its head:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>A page title</title>
</head>
<body>
  <p>Hello</p>
</body>
</html>
```

| Part | Why it is needed |
| :-- | :-- |
| `<!DOCTYPE html>` | Switches the browser into **standards mode**, so it follows the modern rules |
| `<html lang="en">` | Names the language, for translation, pronunciation, and spelling |
| `<meta charset="utf-8">` | Tells the browser how to read the letters |
| `<title>` | Names the page. Required in every document |

For a page that will be used on phones (that is, almost every page), also add the **viewport** line. Together, these make a good **starting template**:

```html
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Page title | Site name</title>
```

## What Goes Where

Order matters a little in the head. A good habit:

1. **`<meta charset>` first,** within the first 1024 bytes of the file, so the browser knows how to read everything after it.
2. **`<meta name="viewport">` and `<title>`** next.
3. **Other `<meta>` and `<link>` tags:** description, canonical address, icons, social previews.
4. **Stylesheets,** so the page can be styled as early as possible.
5. **Scripts,** usually with `defer`, so they do not block the page from appearing.

You will learn the reasons for each choice in the lessons that follow.

## What Can Go in the Head?

Only a short list of elements is allowed in `<head>`:

| Element | Purpose |
| :-- | :-- |
| `<title>` | The page name (required) |
| `<meta>` | Information about the page |
| `<link>` | A relationship with another file, such as a stylesheet or icon |
| `<style>` | CSS inside the page |
| `<script>` | JavaScript (or data) |
| `<base>` | The base address for relative links |
| `<noscript>` | What to show when scripts are off (limited use in the head) |
| `<template>` | A fragment that is not shown until script uses it |

If you put something else in the head, such as a `<div>` or a `<p>`, the browser **closes the head early** and starts the body. Everything after that point is treated as body content, including any `<meta>` or `<link>` tags that follow. That is a common cause of "my tags do nothing" bugs.

## Good Habits from the Start

1. **Always include `lang`, `charset`, `viewport`, and `title`.** The four basics.
2. **Give every page its own title and description.** Copy-pasted ones help no one.
3. **Do not block the page.** Load scripts with `defer`, and keep the head light.
4. **Never disable zoom.** People with low vision rely on it.
5. **Do not trust any value that comes from a visitor** when you build a head on a server. Escape it.

:::warning The head is public
Everything in the head, including comments, is visible to anyone who views the page source. Never put passwords, private notes, internal server names, or unreleased plans in it.
:::

## Accessibility at a Glance

- **`lang` on `<html>`** lets screen readers choose the right pronunciation, and browsers offer correct translation and spell checking.
- **A unique, descriptive `<title>`** is the first thing a screen reader announces on every new page, and the label in the browser's tab list and history.
- **A correct `viewport`,** without `user-scalable=no`, lets people zoom.
- **`charset`** keeps text readable in every language, including text read aloud.
- **A stylesheet that loads reliably** keeps contrast, focus rings, and layout intact.
- **Scripts that load without blocking** keep the page usable quickly, including with assistive technology.

## Security and Privacy Notes

- **Anything in the head is public.** Do not put secrets there, not even in comments or hidden `meta` tags.
- **Scripts and styles from other sites run with full power** on your page. Load only what you trust, pin versions, and use Subresource Integrity where you can. See [Third-Party Content Security](/tutorials/html/embedded-content/third-party-content-security).
- **A `<base>` tag changes every relative link and form address.** An attacker who can inject one can redirect your visitors. Keep it out unless you need it, and put it carefully.
- **If a server builds the head from visitor input** (for example, a title that includes a search term), **escape it**, so no one can inject extra tags.
- **A Content-Security-Policy in a `<meta>` tag** helps, but a response header is stronger.
- **Metadata can reveal more than you think:** editor names in comments, internal paths in script addresses, and draft notes. Review the source before publishing.

## Global Audience Notes

- **Set `lang`,** and use language codes that match your content (`en`, `hi`, `ar`, `pt-BR`). For right-to-left languages, also set `dir="rtl"`.
- **Always use UTF-8** (`<meta charset="utf-8">`), which covers every language. Save your files in UTF-8 as well.
- **Write the title and description in the language of the page,** and keep titles short enough that translations do not become too long.
- **Tell search engines about other language versions** with `<link rel="alternate" hreflang="…">`.
- **Think about slow connections:** a lean head, deferred scripts, and a small stylesheet help most where the network is weakest.
- **Use the viewport tag,** because in many regions, most visitors use phones.

## Common Mistakes to Avoid

1. **No `<title>`,** or one title for the whole site.
2. **No `charset`,** so accents and symbols break.
3. **No `viewport`,** so phones show a tiny desktop page.
4. **Disabling zoom** with `user-scalable=no` or `maximum-scale=1`.
5. **Putting `<div>` or text in the head,** which ends the head early.
6. **Blocking scripts in the head** with no `defer`.
7. **Forgetting `lang` on `<html>`.**
8. **Missing doctype,** so the browser enters quirks mode.
9. **Duplicate or conflicting tags** (two titles, two viewports).
10. **Secrets in comments** or metadata.
11. **A `<base>` tag added without thinking,** breaking every relative link.
12. **Copying one head to every page,** with the same title and description.

## Key Takeaways

- The **head** holds **metadata**: information about the page, for browsers, search engines, social apps, and assistive technology.
- Every page needs a **doctype, `lang`, `charset`, and `title`**, and nearly every page needs a **viewport** tag.
- Put `charset` first, then the viewport and title, then other `meta` and `link` tags, then styles, and then scripts with `defer`.
- Only `title`, `meta`, `link`, `style`, `script`, `base`, `noscript`, and `template` belong in the head.
- Give **each page its own title and description**.
- **Never disable zoom,** and never hide secrets in the head.
- Treat third-party files and server-built values with care.
- Use UTF-8 and `lang`, write for your audience's language, and keep the head light for slow connections.
